# W47 Simple3D — FlashFPS + GPU KD-tree vs FlashFPS + STEP

**52개 카테고리 검증 완료, 실패 0개.** 전체 추론이 빨라진 카테고리는 **41/52개**임. MiniShift는 12개 모두, Anomaly-ShapeNet은 40개 중 29개가 빨라졌음.

## 1. 비교 조건

- 기존판: **FlashFPS + CuPy GPU KD-tree**. STEP판: 같은 FlashFPS를 유지하고 **FPFH용 전체 점 120-NN만 STEP 기반 탐색으로 교체**함. 집계 128-NN과 평활화 12-NN에는 두 방식 모두 기존 GPU KD-tree를 사용함. FPFH 40·80·120 계산 방식도 그대로임.
- MiniShift 정상 1,017개·테스트 1,560개, Anomaly-ShapeNet 정상 160개·테스트 1,312개. STEP판은 카테고리별 메모리뱅크를 새로 구성함. 이전 기준판과 입력 목록·환경 기록이 일치하는지 검증함.
- RTX 5080에서 실행함. 기준판은 과거 동일 설정으로 측정한 결과라, 실행 시점에 따른 변동을 배제할 수 없음. 전체 추론 시간은 특징 추출+점수 계산이며 입력 대기·결과 저장·지표 계산은 제외함.
- STEP은 논문의 Indexing STEP 원리를 가져온 자체 구현임. [논문](https://doi.org/10.1016/j.jpdc.2025.105187) · [캡슐 재실행 A/B](../../method12/markdown/W47_Simple3D_capsule_STEP_FlashFPS_comparison.md)

## 3. 어디서 시간이 줄었나

아래 단계별 표만 **테스트 샘플 수로 가중**함. STEP의 군집 생성과 탐색은 120-NN 전체 시간에 이미 포함돼 있음. 두 보간·FPS·집계/평활화 조회는 각각의 호출을 합산함.

| 테스트 단계 (ms/샘플) | MiniShift | Anomaly-ShapeNet |
|---|---:|---:|
| FPFH 120-NN 전체 | 1,254.35 → 654.78 (−599.57) | 175.95 → 120.23 (−55.72) |
| ↳ STEP 군집 생성 | — → 339.51 | — → 94.45 |
| ↳ STEP 탐색 | — → 314.39 | — → 25.53 |
| FPFH 계산 (40·80·120) | 46.62 → 48.21 (+1.59) | 5.35 → 6.37 (+1.02) |
| 법선 계산 | 105.77 → 109.32 (+3.56) | 12.85 → 13.02 (+0.17) |
| 대표점 선택 (집계+평활화) | 328.64 → 338.53 (+9.89) | 42.62 → 44.57 (+1.95) |
| 집계용 128-NN + 평활화용 12-NN | 53.85 → 55.36 (+1.51) | 42.27 → 44.66 (+2.40) |
| 점수 보간 2회 | 295.24 → 305.62 (+10.38) | 36.52 → 38.61 (+2.09) |

- MiniShift에서는 FPFH용 이웃 탐색에서 가장 큰 절감이 나왔고, 12개 카테고리 모두 전체 추론이 빨라졌음.
- Anomaly-ShapeNet에서 느려진 11개: `eraser0` (+40.4ms), `jar0` (+35.1ms), `ashtray0` (+33.6ms), `vase2` (+32.7ms), `bag0` (+25.7ms), `headset1` (+16.2ms), `cap0` (+13.1ms), `bottle3` (+9.7ms), `vase3` (+4.2ms), `bowl4` (+2.9ms), `bowl5` (+1.6ms). 군집 생성 시간까지 포함해서 비교해야 하며, 느려진 원인을 군집 생성 하나로 단정할 수는 없음.
- GPU 전체 VRAM 표본에는 화면 출력·다른 프로세스도 포함됨. PyTorch 최대 할당은 CuPy 할당을 포함하지 않음.
- 평균 지표가 거의 같다고 해서 점별 점수나 순위까지 모두 같다는 뜻은 아님. 이전 캡슐 A/B에서도 동점 순서 차이와 점별 점수 차이가 관찰됨.
