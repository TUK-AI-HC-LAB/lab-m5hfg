# W48 Simple3D — 어떤 실험을 왜 이 순서로 했는가

**출발 질문:** 고해상도 점군에서 미세 결함을 놓치지 않으면서 Simple3D의 처리 시간을 줄일 수 있는가?

W48의 목적은 가속 기법을 많이 적용하는 것이 아니라, **어떤 계산을 줄여도 탐지 결과가 유지되는지, 그리고 줄이기 어려운 계산은 왜 남는지** 확인하는 것이었음. 아래는 각 단계의 결과가 다음 선택으로 이어진 흐름임.

## Simple3D는 어떤 순서로 처리하는가?

아래 수치는 W48의 MiniShift·Anomaly-ShapeNet 실행 설정임. A~H는 처리 단계이고, 아래 1~7은 실험 순서임.

| 단계               | 입력 → 처리 → 출력                                                                   | W48에서 무엇을 했는가                                                                                      |
| ---------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| A. 입력과 법선        | 원본 점군 → 각 점 주변에서 표면에 수직인 방향(법선) 계산 → 좌표와 법선                                    | Open3D CPU 법선 계산 유지. 캡슐은 물체 한 개당 50만 점.                                                            |
| B. FPFH용 이웃 탐색   | 원본 좌표 → 검색 구조 생성 → 각 원본 점마다 가까운 점 120개의 순서 있는 목록                               | GPU KD-tree에서 STEP 계열 탐색으로 교체. 이후 조회 순서·정렬과 인덱스 생성·경계를 각각 시험함.                                     |
| C. 점별 FPFH 특징    | 점과 이웃의 좌표·법선 → 각 점의 SPFH(주변 기하 관계를 담은 중간 히스토그램) → 자기 SPFH와 주변 SPFH를 합쳐 FPFH    | 120개 목록의 앞 40·80·120개를 각 스케일에 사용함. 안 쓰이는 FPFH를 생략하면 B도 줄일 수 있는지 의존성을 추적함.                          |
| D. 대표점 선택과 특징 집계 | 원본 좌표에서 대표점 4,096개 선택 → 대표점마다 좌표상 가까운 이웃 128개 찾기 → 해당 점들의 특징 평균                | 대표점 선택만 FlashFPS 계열 혼합판으로 변경. 128개 이웃 탐색과 평균은 유지함. SHOT 시험에서는 B~D의 **특징 생성 경로**를 교체하되 대표점 좌표는 고정함. |
| E. 정상 뱅크와 대표점 점수 | 학습: 정상 대표점 특징 → 5% coreset으로 정상 뱅크 구성. 테스트: 대표점 특징과 뱅크 비교 → 가장 가까운 정상 특징까지의 거리 | 점수 공식과 뱅크 선택 규칙은 유지. SHOT는 특징이 달라 기존 뱅크를 재사용하지 않고 새로 구성함.                                          |
| F. 1차 점수 보간      | 대표점 4,096개의 이상 점수 → 원본 각 점에서 가까운 대표점 3개의 점수를 거리로 가중 평균 → 1차 포인트 점수             | 전체 거리 정렬을 동점 보존 Top-3로 교체. 거리를 구하는 계산과 가중 평균은 그대로 둠.                                               |
| G. 점수 평활화와 2차 보간 | 평활화 중심점 1,024개 선택 → 각 중심점 주변 12개 점수 평균 → 원본 각 점에 다시 보간                         | 기존 FPS·12-NN·전체 정렬 보간 유지. 이 12개는 **점수**를 평균하기 위한 이웃임.                                              |
| H. 최종 점수와 평가     | 최종 포인트 점수 → 상위 80개 평균으로 물체 점수 → 정답과 비교해 AUROC/AP 산출                            | 그대로 유지. F의 Top-3와 H의 상위 80개 평균은 서로 다른 연산임.                                                         |

**헷갈리기 쉬운 구분:** B의 **120개**는 각 원본 점의 FPFH를 만들기 위한 이웃이고, D의 **128개**는 각 대표점에서 이미 만든 특징을 모으기 위한 이웃임. F의 **3개**는 특징을 만드는 이웃이 아니라 **대표점 점수를 원본 점에 전달**할 때 사용하는 이웃임.

## 1. 먼저 캡슐에서 어느 단계가 빨라지는지 분리함 [D → B → F]

- **왜 했나:** FlashFPS, STEP, Top-3를 한꺼번에 넣으면 어느 변경이 시간을 줄였고 어느 변경이 점수를 바꿨는지 구분하기 어려움.
- **어떻게 바꿨나:** D에서 전체 점을 대상으로 하던 기존 FPS 대신, 원본 인덱스의 25%를 고정 시드로 후보로 잡고 그중 2,048개를 FPS로 선택한 뒤 미선택 후보에서 2,048개를 원래 순서대로 채웠음. B에서는 FPFH용 120-NN만 STEP 계열 탐색으로 바꿨고, D의 128-NN과 G의 12-NN은 GPU KD-tree를 유지함. 마지막으로 F의 보간 정렬만 바꿈.
- **무엇을 확인했나:** GPU KD-tree 기준판에 FlashFPS(대표점 선택), STEP(FPFH용 이웃 탐색), 선택 Top-3(점수 보간)를 차례로 추가해 각각의 추가 효과를 비교함. 마지막 구성은 기준판보다 평균 추론이 47% 빨랐지만, FlashFPS와 STEP을 추가할 때 점수도 일부 달라졌음.

## 2. Top-3만 바꿔 전체 52개 카테고리에서 검증함 [F]

- **왜 했나:** 점수를 각 원본 점으로 옮기는 보간에는 가까운 중심점 3개만 필요한데, 기존에는 모든 중심점의 거리를 정렬했음. 불필요한 정렬만 줄이면 결과를 유지할 수 있다는 가설을 검증함.
- **무엇을 확인했나:** 4,096개 중심점 보간만 변경하고, 동점은 기존 정렬로 확인함. 52개 카테고리에서 점별 이상 점수·메모리뱅크·AUROC/AP가 모두 같았음. 카테고리 평균 추론 시간은 MiniShift 4.50%, Anomaly-ShapeNet 3.47% 감소했음.

## 3. FPFH용 이웃 조회에서 군집 정렬을 먼저 살펴봄 [B: 조회]

- **왜 했나:** Top-3 적용 이후에도 큰 병목은 각 점의 가까운 이웃 120개를 찾는 과정이었음. 조회 때 군집 경계까지의 최소 가능 거리를 전부 정렬하는 비용을 줄일 수 있는지 확인하고자 했음.
- **왜 방문 순서가 중요한가:** 가까운 군집부터 보면 괜찮은 후보 120개를 일찍 채울 수 있음. 그 뒤 어떤 군집의 최소 가능 거리가 현재 120번째 후보보다 크면 그 군집은 통째로 건너뛸 수 있음. 이때의 정렬은 **군집 방문 순서**를 정하는 것이며, F에서 줄인 보간 정렬과 다름.
- **무엇을 확인했나:** 군집 정렬을 없애니 이웃은 같았지만, 가까운 군집부터 방문하는 순서가 깨져 확인할 후보가 늘었고 조회는 오히려 느려졌음. 그래서 방문 순서는 유지하고 정렬 구현만 Radix로 교체함. 전체 추론은 capsule에서 5.00%, vase9에서 2.27% 감소했고, 두 카테고리의 점수와 지표는 같았음.

## 4. 직접 쓰지 않는 FPFH를 생략할 수 있는지 확인함 [D → C → B 의존성]

- **왜 했나:** 최종 특징은 대표점 주변에서 모으므로, 실제로 쓰는 점의 FPFH만 만들면 이웃 탐색도 크게 줄일 수 있다는 가설을 세움.
- **무엇을 확인했나:** 24개 샘플의 특징 의존 관계를 추적함. MiniShift 표본에서 직접 쓰는 FPFH는 약 54%였지만, 그 FPFH가 주변 점의 중간 특징(SPFH)을 참조하므로 약 99.94%의 점에서 120-NN 조회가 여전히 필요했음. Anomaly-ShapeNet 표본에서는 100%였음.

## 5. 기존 지역 특징 SHOT로 교체해 속도와 정확도를 비교함 [B~D: 특징 경로]

- **왜 했나:** 원본 전체의 FPFH를 계산한 뒤 모으지 않고, 대표점 주변만 보고 특징을 직접 만들면 전체 점의 120-NN 탐색을 피할 수 있음. 선행연구 조사에서 이 발상 자체는 이미 알려져 있어, SHOT를 새 방법이 아닌 비교 기준으로 선택함.
- **무엇을 확인했나:** capsule에서 입력·대표점·후처리를 유지하고 정상 뱅크를 새로 구성함. SHOT의 평균 추론 시간은 35.8% 줄었지만, 물체 AUROC는 93.17% → 59.33%, 포인트 AUROC는 81.82% → 57.25%로 하락함. 반경 기반 패치와 특징 차원, CPU/GPU 구현도 달라 SHOT 표현 하나만의 영향으로 단정할 수 없음. 평가 수치는 확보했고, 사례 그림은 생성되지 않았음.

## 6. FPFH를 유지하고 인덱스 구성만 Morton 방식으로 교체함 [B: 구조 생성]

- **왜 했나:** 현재 STEP 계열 구현은 점군마다 K-means 군집을 만들기 위해 50회 갱신함. 점을 공간 순서로 정렬해 묶으면 이 준비 비용을 줄이고, 원본 좌표로 정확한 이웃을 계속 찾을 수 있는지 확인하고자 했음.
- **무엇을 확인했나:** 6개 표본에서 이웃 순서와 FPFH 값이 모두 같았음. 구조 생성은 빨라졌지만, capsule은 묶음 경계가 넓어져 후보 검사량이 늘었고 **생성+조회 합계**가 57.7% 증가함. vase9에서는 같은 합계가 39.4% 감소함. 일괄 교체 기준을 충족하지 못해 전체 추론 실험으로 확대하지 않음.
- **무엇을 배웠나:** 인덱스를 싸게 만드는 것만으로는 충분하지 않음. 묶음 경계가 느슨해져 후보가 늘면 준비 비용을 줄인 이득이 사라질 수 있음. 두 물체의 결과만으로 점 수가 원인이라고 단정할 수는 없음.

## 7. Morton 묶음은 유지하고 탐색 경계만 직육면체로 바꿈 [B: 경계와 가지치기]

- **왜 했나:** 6번에서 구조 생성은 빨라졌는데 조회 후보가 늘었음. 점을 묶는 방식의 문제인지, 각 묶음을 큰 구로 감싼 탓인지 분리하기 위해 **같은 Morton 점 묶음에서 경계만** 구와 직육면체(AABB)로 비교함.
- **어떻게 바꿨나:** 각 묶음의 x·y·z 최솟값과 최댓값으로 직육면체를 만듦. 쿼리 점에서 직육면체까지의 최소 가능 거리가 현재 120번째 이웃 거리보다 **엄격히 클 때만** 묶음을 건너뜀. 원본 좌표, 묶음의 점 순서, 거리 동점 규칙, FPFH와 그 이후 단계는 유지함.
- **표본 3개:** Morton+구 → Morton+AABB로 바꾸자 쿼리당 후보 거리 계산이 약 13,778회 → 5,438회로 감소함. 이웃 순서와 FPFH 값은 같았고, 구성+조회 합계는 기존 K-means+구 546.2ms 대비 437.9ms로 19.8% 감소함. 세 표본 모두 기준을 통과해 전체 캡슐로 확대함.
- **캡슐 전체:** 정상 54개로 버전별 뱅크를 새로 만들고 테스트 130개를 비교함. 같은 Radix 조회 방식 계열에서 K-means+구 대비 Morton+AABB의 인덱스 구성은 **329.2 → 1.9ms**, 조회는 **248.4 → 432.9ms**였음. 조회가 느려졌지만 준비 비용 감소가 더 커 전체 추론은 **1,498.85 → 1,376.17ms(-8.18%)**였음. **6,500만 점에서 점수 불일치 0개**, 물체 점수·정상 뱅크·AUROC/AP도 동일했음.
- **범위:** 캡슐 한 카테고리에서 버전별 1회 실행한 결과임. 다른 카테고리나 반복 실행에서 같은 개선율을 보장하지 않음.

## W48에서 남은 연구 질문

**정확한 FPFH 이웃을 유지하면서, 탐색 구조를 만드는 비용과 실제로 검사하는 후보 수를 함께 줄일 수 있는가?**

Top-3와 Radix는 결과를 유지하는 가속 기준선으로 남김. FPFH 출력 행 생략은 주요 탐색을 거의 줄이지 못했고, 이번 SHOT 설정은 정확도가 크게 떨어졌음. Morton+AABB는 **캡슐에서 정확도를 유지하며 준비 비용을 줄일 수 있음**을 확인했지만, 기존 K-means에 비해 조회 비용은 여전히 높음. 다음에는 이 방식이 다른 점군에서도 재현되는지, 그리고 경계 변경으로도 남는 후보 검사를 어떻게 줄일 수 있는지 확인해야 함. 기존 기법을 교체한 결과를 새 알고리즘의 기여로 주장하지 않음.
