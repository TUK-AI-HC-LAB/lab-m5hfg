## 0. 이 문서에서 설명할 것

**같은 물체의 이상을 찾더라도, 입력이 달라지면 어떤 정보를 얻고 어떤 관계를 처리해야 하는지가 달라진다.** 아래 비교표는 공통 목표와 차이를 만드는 요소를 나눈다.

비교 범위는 **2D = 단일 RGB 이미지**, **3D = XYZ Point Cloud**, **Multi-view = 같은 물체의 여러 방향 RGB 이미지**로 고정한다. XYZ만 있는 3D 입력에는 색 정보가 없다. 여러 View의 Point Cloud를 합치거나 RGB와 3D를 함께 쓰는 설정도 있지만, 여기서는 세 입력 방식의 차이를 먼저 설명한다.

## 1. 비교에 필요한 용어

Point Cloud 같은 기본 용어는 영어로 통일하고, 범주 간 특징 혼동 같은 고급 개념은 한국어로 설명한다.

### 1.1 3D Point Cloud 관련 용어

| 용어                                         | 뜻                                                      | 예시                       |
| ------------------------------------------ | ------------------------------------------------------ | ------------------------ |
| Point Cloud (포인트 클라우드) | 물체 표면을 나타내는 3차원 좌표점의 집합                                | 물체 표면에 붙인 점 스티커들의 위치     |
| Point (포인트) | 위치 정보 `(x, y, z)`를 가진 점 하나                             | 점 스티커 하나의 위치             |
| Depth Map (깊이 지도) | 행·열 격자의 각 픽셀에 깊이 값을 저장한 데이터                            | 모눈종이에 적은 칸별 거리표          |
| Organized Point Cloud (정렬된 포인트 클라우드) | 이미지 행·열 배열을 유지하며 위치마다 XYZ 저장                           | 모눈종이 칸마다 적은 3D 주소        |
| Unorganized Point Cloud (비정렬 포인트 클라우드) | 이미지 격자 연결 없이 점을 목록으로 저장                                | 칸 구분 없이 나열한 3D 주소 목록     |
| Surface Curvature (표면 곡률) | 3D 표면의 휘어짐을 나타내는 정보                                    | 종이를 구부린 정도               |
| Surface Normal (표면 법선) | 국소 표면에 수직인 방향                                          | 표면에 직각으로 세운 막대의 방향       |
| Point Cloud Neighborhood Search (포인트 클라우드 이웃 탐색) | 3D 좌표 거리로 주변 점 집합 구성                                   | 실제 거리로 가까운 이웃 찾기         |
| Voxel (복셀) | 3차원 공간을 나눈 작은 상자 모양의 격자 칸                              | 공간을 나눈 작은 상자 칸           |
| Voxelization (복셀화) | Point Cloud가 있는 공간을 Voxel로 나누고, 같은 칸에 속하는 점들을 묶는 과정; 점의 위치는 바꾸지 않음 | 점에 상자 격자를 씌워 같은 칸끼리 묶기   |
| 국소 기하 특징 | 주변 점들의 기하 관계를 요약한 특징                                   | 작은 표면 조각의 모양 요약표         |
| 3D Displacement Vector (3D 변위 벡터) | 점의 세 축 이동량 `(Δx, Δy, Δz)`                              | 오른쪽·앞·위로 얼마나 움직였는지 적은 메모 |

Depth Map의 격자는 **2차원 픽셀 배열**이고 Voxel은 **3차원 공간의 격자 칸**이다. 격자의 옆 픽셀이 실제 3D 공간에서도 가까운 것은 아니다. 물체 경계에서는 멀리 있는 배경일 수 있다. Organized는 배열 구조를 뜻하며, 관측 좌표를 서로 맞추는 Registration과 다르다.

### 1.2 Multi-view 관련 용어

| 용어                                  | 뜻                          | 쉬운 비유                  |
| ----------------------------------- | -------------------------- | ---------------------- |
| View (시점) | 물체를 관측하는 카메라 방향·위치         | 컵을 정면·옆·위에서 보는 위치와 방향  |

## 2. 무엇이 같고 무엇이 다른가?

| 차이를 만드는 요소        | 2D                          | 3D — Point Cloud                     | Multi-view                                |
| ----------------- | --------------------------- | --------------------------------- | ---------------------------------- |
| **공통 목표**         | 물체의 이상 여부와 이상 위치 찾기         | 동일                                | 동일                                 |
| **학습 원리의 공통점**    | Normal Data로 정상 기준을 학습·구성할 수 있음  | 동일                                | 동일                                 |
| **입력 단위**         | 사진 한 장                      | 표면의 XYZ 좌표점 집합                    | 같은 물체의 여러 방향 사진                    |
| **직접 관측하는 정보**    | 색·무늬·밝기·윤곽                  | 깊이와 표면 형상                         | View별 외관과 한 장에서 안 보이는 면              |
| **결함의 쉬운 예시**     | 금속판의 얼룩                     | 금속판의 움푹 팬 부분                      | 뒷면 사진에만 보이는 흠집                     |
| **주변 관계의 표현**     | 행·열 격자에서 옆 픽셀의 위치가 정해짐      | 비정렬 Point Cloud에서는 좌표 거리로 주변 점을 찾아야 함      | 각 사진 내부의 픽셀·패치 관계를 분석하고 View별 결과를 통합 |
| **형상 정보를 다루는 방식** | 영상에 나타난 밝기·윤곽 등에서 형상 단서를 얻음 | 주변 점으로 표면의 방향·휘어짐 등 기하 구조를 추정·표현  | 정면·측면 등 각 View의 외관을 해당 View의 정상 기준과 비교 |
| **추가 처리**         | 이미지 특징 추출과 이상 판단            | 이웃 탐색·기하 특징 추출; 방법에 따라 정렬·Voxelization·복원  | 여러 이미지 처리와 물체 단위 결과 통합             |
| **이상 위치 출력**      | 픽셀·영상 영역                    | Point·표면 영역                         | View별 영상 영역; 물체 단위로 판정 통합            |
| **계산량을 결정하는 요소**  | 이미지 해상도와 모델                 | 점 수·이웃 크기·표현 방식과 모델               | View 수·각 이미지 해상도·통합 방식과 모델           |
| **2D 대비 추가 과제**   | 비교 기준                       | **점들로부터 표면 구조를 파악하면서 미세한 변형을 보존** | **여러 장의 촬영·처리에 따른 비용 증가**      |

**3D에서는 표면 기하 처리의 차이를, Multi-view에서는 관찰 범위의 확대와 촬영·처리 비용을 중심으로 비교한다.**

## 3. 3D는 단일 2D 이미지에 비해 무엇을 더 처리해야 하는가?

### 3.1 가장 쉬운 예시: 금속판의 움푹 팬 부분

**3D에서는 좌표점들을 보고, 그 점들이 만드는 표면이 정상 형상과 다른지 판단한다.**

![정상 금속판과 움푹 팬 금속판의 3D 포인트 클라우드 및 단면 비교](images/2d_3d_multiview/pointcloud_dent_example.png)

**그림.** 왼쪽은 평평한 정상 표면, 오른쪽은 일부가 안쪽으로 들어간 표면이다. 아래 단면에서는 높이 차이를 확인할 수 있다. 빨간 점은 설명을 위해 결함 영역을 강조한 것이다.

- **2D에서 보는 것:** 어두운 자국이 보인다. 밝기만으로는 얼룩·그림자·함몰을 구분하기 어려울 수 있다.
- **3D에서 얻는 이점:** 표면 좌표가 실제로 안쪽으로 들어갔는지 확인할 수 있다.
- **3D에서 더 처리할 것:** 한 점의 좌표만으로 결함을 판단하지 않고, 주변 점들과 비교해 표면이 어떻게 이어지는지 파악해야 한다.

반대로 색만 달라진 얼룩은 XYZ 좌표만으로 구분하기 어려울 수 있다. 3D의 정보는 2D의 모든 정보를 포함하는 것이 아니라, 이 비교에서는 **색 대신 표면 형상을 직접 제공하는 정보**다.

### 3.2 좌표가 있는데 왜 표면을 다시 파악해야 하는가?

Point Cloud에는 좌표가 있지만, 비정렬 Point Cloud에서는 사진처럼 행·열에 따른 연결 관계가 주어지지 않는다. 또한 점 하나에는 그 주변이 평면인지, 곡면인지, 함몰인지가 직접 적혀 있지 않다.

**예시 흐름: 주변 점 찾기 → 점들이 이루는 표면의 방향·휘어짐 추정 → 정상 표면과 다른지 판단.** 이는 개념 설명이며 모든 모델이 이 단계를 별도 모듈로 수행한다는 뜻은 아니다.

| 단계        | 금속판 예시                         | 추가로 처리하는 이유                          |
| --------- | ------------------------------ | ------------------------------------ |
| 주변 점 찾기   | 한 점 가까이에 있는 점들을 모음             | 점 목록에서 앞뒤에 있는 점이 공간적으로도 가까운 것은 아님    |
| 표면 구조 파악  | 주변 점들이 평평하게 이어지는지, 안쪽으로 휘는지 확인 | 좌표 하나만으로는 함몰의 모양을 알 수 없음             |
| 정상 형상과 비교 | 평평해야 할 부분의 국소 함몰을 구분           | 정상적인 곡면과 모서리도 있으므로 휘었다는 사실만으로 불량은 아님 |

Surface Curvature는 이때 사용할 수 있는 휘어짐 정보다. **Surface Curvature이 크면 무조건 이상이라는 규칙은 아니다.** 캔의 정상 테두리도 많이 휘어져 있지만, 평평해야 하는 옆면의 작은 찌그러짐은 결함일 수 있다. 따라서 **어디에 어떤 표면 구조가 정상적으로 있어야 하는지**가 중요하다.

### 3.3 ‘기하 정보 복원’에서 정확히 무엇이 어려운가?

복원 기반 방법에서는 작은 찌그러짐을 놓치고 물체의 전체 모양만 그럴듯하게 복원할 수 있다. 예를 들어 정상 캔과 찌그러진 캔 모두 전체적으로 원통처럼 보이므로, **전체 형상을 잘 복원했다는 것만으로 작은 결함까지 구분했다고 할 수 없다.** 국소 표면의 세부 구조를 보존하고 비교해야 한다.

> 2D는 사진에 나타난 외관을 비교한다. 3D Point Cloud는 표면 좌표를 제공하지만, 그 점들의 이웃 관계와 휘어짐을 파악해야 형상 결함을 구분할 수 있다. 깊이를 알 수 있다는 이점과, 점들로부터 표면 구조를 처리해야 한다는 과제가 함께 있다.

## 4. Multi-view의 이점과 비용

### 4.1 더 많은 면을 검사할 수 있다

같은 물체를 정면·측면·뒷면에서 촬영하면 한 장에서 보이지 않던 면을 검사할 수 있다. 예를 들어 캔 뒷면의 흠집은 뒷면 사진을 추가하면 확인할 수 있다.

여기서는 **각 View의 이미지를 해당 View의 정상 기준과 비교하는 방식**을 설명한다. 제품 단위 판정은 “어느 한 면에서라도 결함이 발견되면 불량” 같은 규칙으로 정할 수 있다. 이는 판정 절차이며, 그 자체를 Multi-view의 핵심 난점으로 제시하지 않는다.

### 4.2 단일 이미지 검사보다 늘어나는 비용

| 비용 요소          | 늘어나는 이유                        | 조건                      |
| -------------- | ------------------------------ | ----------------------- |
| 촬영 장비·운영       | 여러 카메라를 설치하거나 물체를 돌려 촬영        | 장비 구성에 따라 달라짐           |
| 계산량            | 제품 하나당 여러 장의 이미지를 검사           | 같은 해상도·모델을 View별로 적용할 때   |
| 처리 시간 또는 연산 장비 | 순차 처리에는 시간이, 병렬 처리에는 추가 자원이 필요 | 촬영·연산 병렬화 방식에 따라 달라짐    |
| 저장량            | 제품 하나의 여러 이미지를 보관              | 원본 이미지를 저장하는 경우         |
| Normal Data 수집      | 각 View의 정상 외관을 보여주는 표본을 확보       | 필요한 표본 수는 학습 방식에 따라 달라짐 |

**최대 메모리 사용량이 View 수에 비례해 반드시 증가하는 것은 아니다.** 이미지를 한 장씩 순차 처리하면 동시 처리에 필요한 메모리를 줄일 수 있다.

### 4.3 View별 Normal Data가 줄어드는 조건

전체 촬영량이 정상 이미지 1,000장으로 고정되어 있다고 가정한다.

| 수집 방식 | View별 정상 이미지 수 |
|---|---:|
| 정면만 촬영 | 정면 1,000장 |
| 다섯 방향에 동일하게 배분 | 각 방향 200장 |

이 조건에서는 각 View의 정상 외관을 학습할 표본 수가 줄어든다. 반면 정상 제품 1,000개를 각각 다섯 방향으로 찍으면 View별로 1,000장을 확보하는 대신 총 촬영량이 5,000장으로 늘어난다. 이는 촬영량을 어떻게 확보·배분하는지에 관한 예시이며, Multi-view의 필연적인 성능 저하를 뜻하지 않는다.

### 4.4 핵심

**Multi-view는 더 많은 면을 검사할 수 있지만, 촬영·데이터 수집·계산·저장 비용이 증가한다.** View별로 이미지를 검사하고 결과를 합치는 현재 비교 조건에서는, 정보가 많다는 이유만으로 탐지 자체가 더 어렵다고 설명하지 않는다.

## 5. 비교할 때 구분할 것

- **3D의 난도를 ‘Surface Curvature 복원’으로 한정하지 않는다.** 기하 특징 계산·표현·복원·분류 등 구현은 다르다. Surface Curvature은 표면 구조를 설명하는 구체적인 예다.
- **Multi-view의 이점과 비용을 구분한다.** 더 많은 면을 관찰할 수 있는 대신 촬영·처리 비용이 증가한다. 정보량 증가 자체를 탐지 난도 증가의 근거로 삼지 않는다.
- **Multi-view와 Multimodal을 구분한다.** 여러 방향의 RGB 사진은 Multi-view다. RGB와 깊이처럼 서로 다른 종류의 정보를 함께 쓰는 것은 Multimodal이다.

### 설명 기준 논문과의 연결

사용자가 지정한 다섯 논문은 3D 설명의 근거다. 각 논문의 전체 방법을 소개하기보다 비교에 필요한 문제를 연결한다.

| 기준 논문 | 비교 설명에 활용하는 내용 | 해석 범위 |
|---|---|---|
| [1] Towards High-Resolution 3D Anomaly Detection | High-Resolution Point Cloud에서 미세한 표면 결함을 다루는 문제 | 세부 기하 정보를 보존하며 처리해야 한다는 근거 |
| [2] CASL | Surface Curvature을 활용한 기하 표현 학습 | Surface Curvature의 활용 사례이며 모든 3D 방법의 필수 단계는 아님 |
| [3] Physics-inspired Pseudo Anomaly Generation and Prototype Feature Guidance | 표면 변형을 모사하고 점의 변위를 이용하는 접근 | 3D 결함을 좌표·표면 변형으로 다루는 사례 |
| [4] A Semantically Disentangled Unified Model | 여러 Category의 의미와 기하 정보를 고려한 특징 복원 | Multi-category는 Multi-view와 다르며, 범주 혼동은 3D만의 문제는 아님 |
| [5] MFF-M3AD | 여러 스케일의 특징 융합·정제·복원 | 작은 구조와 전체 구조를 함께 다루는 사례; 공개 초록·서론 확인 범위 |

Multi-view 부분은 관측 방식과 촬영·처리 비용을 설명하는 배경이며 Real-IAD [7]를 보충 근거로 둔다.
