======================================================================
0단계. 발표 전에 알아야 할 개념
======================================================================

1. Vision Anomaly Detection
  제품 이미지가 정상인지 이상인지 판별하고, 이상이면 어느 위치가 문제인지 찾는 일.

  - image score: 이미지 한 장의 이상 점수 하나.
  - anomaly map: 이미지 위치별 이상 점수 지도.

2. normal 기준
  이상 탐지는 "무엇이 이상인가"보다 "무엇을 정상으로 보고 얼마나 다른가"가 핵심임.

  - PatchCore: 정상 train image의 patch feature memory.
  - RD4AD: 정상 data로 학습한 decoder가 복원한 feature.
  - AnomalyCLIP: normal/abnormal text feature.

3. 공통 framework
  방법마다 내부 알고리즘은 달라도, 설정 읽기·데이터 처리·모델 선택·실행·결과 저장을
  공통으로 만드는 코드 구조.

4. registry
  YAML의 `method` 문자열을 실제 Trainer class와 연결하는 표.

  한 문장 설명:
  "registry는 method 이름을 보고 어떤 Trainer를 실행할지 결정하는 모델 교체 표입니다."

5. limitation과 개선 방향
  - limitation: 코드 구조에서 생기는 제약 또는 비용.
  - 개선 방향: 그 제약을 겨냥한 기존 논문의 방법.
  - 아직 원인이나 개선 효과가 확인되지 않았으면 가설로만 말해야 함.

말할 순서

  - [1, 1, 518, 518]: 결함 mask 1장.
  - [1, 768]: 이미지 전체 feature.
  - [1, 1370, 768]: 위치별 patch feature 1,370개.

6단계. PatchCore limitation을 설명한다. 약 2분
======================================================================

열 자료
  related_work/markdown/W40_기존_method_코드_기반_한계와_개선안_비교.md의 "3. PatchCore"

말할 순서
  1. 정상 train patch feature를 memory bank에 저장함.
  2. coreset이 대표 patch만 남김.
  3. test patch가 memory에서 얼마나 먼지로 이상 점수를 만듦.
  4. memory가 많으면 기준은 촘촘하지만 저장과 nearest-neighbour search 비용이 큼.

현재 evidence
  "현재 재현에서는 coreset을 10%에서 1%로 줄일 때 평균 Image/Pixel AUROC가
   약 0.14%p 낮았습니다. 이는 memory를 줄이는 선택에 성능 trade-off가 있음을
   보여 줍니다."

기존 개선 방향
  "RD4AD는 memory bank를 검색하지 않고 teacher–decoder feature 차이로 이상을 찾는
   대체 계열입니다. 아직 RD4AD가 항상 더 낫다고 주장하지 않고, memory/search 비용을
   없애는 설계라는 점만 연결합니다."

======================================================================
7단계. RD4AD limitation을 설명한다. 약 2분
======================================================================

열 자료
  related_work/markdown/W40_기존_method_코드_기반_한계와_개선안_비교.md의 "4. RD4AD"

말할 순서
  1. teacher feature를 bottleneck과 reverse decoder로 복원함.
  2. teacher feature와 decoder feature의 차이를 anomaly map으로 사용함.
  3. RD++는 RD4AD가 normal feature compactness와 anomaly signal 억제를 직접
     강제하지 않는다고 지적함.
  4. RD++는 contrast/optimal transport와 pseudo anomaly reconstruction을 추가함.

현재 evidence와 주의
  "현재 RD4AD 재현에서 transistor의 Pixel AUROC와 AU-PRO가 평균보다 낮았습니다.
   하지만 원인을 바로 feature limitation이라고 결론내리면 안 됩니다.
   원 논문이 언급한 annotation과 prediction 위치 불일치일 수도 있기 때문에,
   원본 image, mask, anomaly map을 먼저 비교해야 합니다."

======================================================================
8단계. W40의 현재 결론을 말한다. 약 1분
======================================================================

말할 내용
  "공통 framework를 분석해보니, method는 같은 runner를 쓰지만 normal 기준과 score
   계산은 서로 다릅니다. 그래서 limitation도 한 가지가 아닙니다.
   PatchCore에서는 memory–성능 trade-off를 실제 비용까지 측정해야 하고,
   RD4AD에서는 transistor의 낮은 위치 지표가 실제 feature failure인지 map으로
   진단해야 합니다."

현재 주장 범위
  - framework 구조와 method별 code path를 구분함.
  - PatchCore와 RD4AD의 limitation 후보와 기존 개선 논문을 연결함.
  - 아직 새로운 방법의 성능 향상을 주장하지 않음.

질문
  "다음 검증은 PatchCore의 coreset 비율별 실제 memory·검색 시간 측정과,

발표 직전 점검
  [ ] 한 이미지 실행은 evidence라고만 설명했는가?
  [ ] framework의 공통 부분과 Trainer 내부의 method별 부분을 구분했는가?
  [ ] mask는 input이 아니라 평가 정답이라고 말할 수 있는가?
  [ ] PatchCore memory cost와 RD4AD feature limitation을 구분했는가?
  [ ] RD4AD failure 원인을 아직 확정하지 않았다고 밝혔는가?
  [ ] 새 방법의 성능 향상을 주장하지 않았는가?
