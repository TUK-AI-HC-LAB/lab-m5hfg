## 1. 서론

### 1.1 연구 배경과 중요성

- Vision anomaly detection은 이미지의 이상 유무와 이상 위치를 찾는 문제임.
- 산업 이상은 결함 유형을 모두 학습 데이터로 확보하기 어렵기 때문에, 새로운 범주에 적용 가능한 zero-shot 성질이 중요함.
- CLIP 기반 방법은 이미지와 텍스트의 사전학습 표현을 활용해 보지 못한 범주에도 적용하려는 흐름임 [1].

### 1.2 기존 접근의 큰 계열과 한계

- 정상 데이터 기반 one-class 방법: 정상 분포 또는 정상 특징과의 차이로 이상을 찾음. 새로운 이상 유형을 별도로 학습하지 않아도 되지만, 범주 간 일반화와 위치 표현이 제한될 수 있음.
- CLIP 기반 zero-shot 방법: 정상·이상 텍스트 표현과 image feature의 유사도로 이상을 찾음. 범주 일반화 가능성이 있지만, 원래 CLIP은 정상과 이상을 명확히 구분하도록 학습된 모델은 아님 [1].

### 1.3 우리가 집중하는 접근과 남은 문제

- 이번 주 집중 접근: source dataset의 anomaly 정보를 사용해 CLIP adapter를 학습하고, target dataset에 zero-shot 적용하는 AA-CLIP [1].
- 장점: target 범주의 결함 label 없이도 anomaly-aware 표현을 얻는 것을 목표로 함.
- 남은 문제: source supervision을 사용한 설정은 정상 train 이미지만 사용하는 RD4AD와 학습 정보가 다르므로, 두 방법의 점수를 동일한 조건의 성능으로 해석할 수 없음.

### 1.4 원인 가설

- 현재 limitation: 방법 간 결과를 비교할 때 source dataset의 anomaly label 사용 여부가 혼동될 수 있음.
- H1: AA-CLIP의 MVTec 성능은 MVTec train 데이터로 직접 adapter를 학습한 성능이 아니라, source dataset에서 얻은 anomaly-aware adapter의 cross-dataset generalization 성능임.
- H1이 맞다면, protocol에는 source training dataset과 target evaluation dataset이 분리돼 명시돼야 함.

### 1.5 이번 주 선택한 방향

- 이번 주 해결 후보: AA-CLIP의 논문 protocol을 source/target/학습 정보 기준으로 정리함.
- 선택 이유: 구현 또는 수치 비교 전에 공정한 비교 단위를 고정하기 위해서임.
- 이 선택이 H1을 검증하는 방식: 논문 [1]의 실험 설정에서 VisA와 MVTec의 역할을 구분해 확인함.

### 1.6 이번 주 기여 또는 검토 초점

- 핵심 판단: AA-CLIP은 target dataset의 정상 train 이미지로만 학습하는 방법이 아니라, source anomaly dataset으로 adapter를 학습하는 cross-dataset zero-shot 방법임.
- 근거: [1].

## 2. 사전 지식과 문제 정의

### 배경

- AA-CLIP은 CLIP의 image-text 표현을 anomaly detection에 사용하되, residual adapter로 텍스트와 이미지 표현을 단계적으로 적응시키는 방법임 [1].

### 기술 용어

- *zero-shot anomaly detection* [1]: target 범주의 anomaly label로 학습하지 않고, 학습된 표현을 target 이상 탐지에 적용하는 설정.
- *source dataset* [1]: adapter 학습에 쓰는 anomaly annotation 포함 데이터셋.
- *target dataset* [1]: source에서 학습한 adapter를 평가하는 데이터셋.
- *image-level AUROC*: 이미지 전체의 정상/이상 분류 성능. 1에 가까울수록 좋음.
- *pixel-level AUROC*: 픽셀별 이상 위치 판별 성능. 1에 가까울수록 좋음.

### 표기법

| 표기법 | 설명 |
|---|---|
| `D_s` | anomaly supervision을 포함하는 source dataset |
| `D_t` | zero-shot 평가 target dataset |
| `g` | 고정 CLIP backbone |
| `a_t`, `a_v` | text 및 visual residual adapter |

### 정의

정의 1. Cross-dataset zero-shot protocol.
`D_s`로 adapter를 학습하고, `D_t`의 target 범주 label을 adapter 학습에 사용하지 않은 채 평가하는 protocol이다. 이 brief에서는 `D_s`와 `D_t`를 명시하지 않은 성능 비교를 같은 protocol으로 간주하지 않는다.

### 문제 정의

문제 1. AA-CLIP의 MVTec AD zero-shot 평가 설정 이해.
source anomaly dataset `D_s`와 target dataset `D_t`가 주어졌을 때, adapter를 `D_s`에서 학습한 뒤 `D_t`의 이미지 이상 점수와 pixel anomaly map을 예측한다. 성공 기준은 `D_t`의 image-level 및 pixel-level 지표이며, 학습 정보의 범위는 `D_s`와 `D_t`를 분리해 해석한다.

## 3. 관련 연구

### 3.1 현재 문제를 푸는 큰 연구 흐름

- one-class anomaly detection:
  - 정상 train 이미지의 특징 또는 복원 오차로 이상을 찾음.
  - 대표 방법: RD4AD [2].
  - 현재 문제와의 연결: target 정상 데이터만 이용하는 기준점임.
- CLIP-based zero-shot anomaly detection:
  - 사전학습 image-text 표현을 anomaly score로 연결함.
  - 대표 방법: AA-CLIP [1].
  - 현재 문제와의 연결: source anomaly supervision으로 target generalization을 목표로 함.

### 3.2 현재 원인 가설에 대응하는 관련 연구

- H1과 관련된 prior work: AA-CLIP [1]은 source 데이터에서 anomaly-aware text anchor와 visual adapter를 학습한 뒤, 다른 dataset에 적용하는 실험을 제시함.
- 적용 시 주의점: target 지표만 비교하면 source supervision의 차이가 사라지므로, 학습 데이터의 범위를 함께 기록해야 함.

### 3.3 이번 주 해결 후보 요약

- 후보 A: target one-class protocol과 AA-CLIP cross-dataset protocol을 분리해 기록.
  - 관련 연구 근거: [1], [2].
  - 왜 필요한가: 학습 정보가 다른 방법의 결과를 공정하게 해석하기 위해서임.
  - 이번 주 판단: 선택.

## 4. 선택한 방법 또는 절차

- 선택한 절차: AA-CLIP 논문 [1]의 source/target protocol과 adapter 학습 단계를 정리함.
- 기존 연구와의 차이: 새 모델·loss·protocol 변경을 제안하지 않음.
- 구현 또는 protocol 변경: 논문과 공식 코드의 기본 FP32 설정과 달리, 중단된 run을 이어서 실행할 때는 TF32와 BF16 AMP를 사용하도록 변경함. 앞선 checkpoint는 FP32 조건에서 생성됐으므로, 재개 run은 FP32와 TF32+BF16 AMP가 섞인 조건임. 이 사실을 결과 해석 시 별도로 기록해야 함.
- H1과의 연결: source 학습과 target 평가를 분리해 기록하는 것으로 H1의 전제를 확인함.

## 6. 논의

- 지금 주장할 수 있는 것: AA-CLIP은 source anomaly supervision을 이용하는 cross-dataset zero-shot 설정으로 읽어야 함 [1].
- 아직 주장할 수 없는 것: 현재 환경에서의 성능, 재현 가능성, RD4AD 대비 우위.
- 남은 불확실성: source dataset 선택이 target 성능에 미치는 정도.
- 다음 검증: 구현 결과가 준비된 뒤에도 source/target protocol을 유지한 별도 evidence로 평가함.
