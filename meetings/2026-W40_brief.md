### 이번 주 변화

- MVTec loader가 `VAL`일 때 더 이상 존재하지 않는 `val/` 폴더나 test 폴더를 읽지 않고, `train/good`에서 정상 이미지를 분리하도록 수정했다.
- 분할 뒤에도 `TRAIN ∩ VAL = ∅`, `VAL ∩ TEST = ∅`임을 코드로 확인했다. `bottle`에서는 각각 188장, 21장, 83장이다.
- validation 분할 전(209장 train)과 후(188장 train)의 수치 차이를 확인하기 위해 12개 method를 같은 `bottle`, seed 0, 기본 config로 재실행했다.
- 11개 방법은 결과 CSV를 생성했다. 당시 CLIP 재정규화 조건의 PatchCore·PaDiM·WinCLIP·COAD·RD·RD-Orig·PromptAD·Dinomaly·UniAD·AnomalyCLIP은 Image AUROC가 거의 변하지 않았고, SimpleNet만 한 seed에서 크게 하락했다. 이후 AnomalyCLIP도 WinCLIP처럼 공통 ImageNet 정규화 입력을 그대로 쓰도록 통일했고, `bottle` 결과는 Image AUROC 0.8897, Pixel AUROC 0.9027이었다. 이는 관찰 결과이며 일반 결론은 아니다.

## 1. 서론

### 1.1 연구 배경과 중요성

- 산업 이상 탐지는 정상 제품의 사진을 기준으로 결함 이미지와 결함 위치를 찾는 문제다.
- PatchCore, PaDiM, SimpleNet, RD 같은 방법은 정상 train 이미지를 이용해 정상 기준을 만든다 [1-4]. 따라서 어떤 정상 이미지를 학습에 쓰고, 어떤 이미지를 검증용으로 남기는지는 실행 결과의 해석과 관련된다.
- 공통 framework는 서로 다른 방법의 내부 계산을 같게 만드는 것이 아니라, data loading·method 선택·실행·metric·CSV 저장을 공통화한다.

### 1.2 기존 접근의 큰 계열과 한계

- **Memory/feature 기준 방법**: PatchCore·PaDiM은 정상 feature와의 거리로 이상을 계산한다. 정상 학습 이미지가 줄면 기준 feature의 밀도가 달라질 수 있다.
- **학습형 방법**: SimpleNet·RD·Dinomaly·UniAD 등은 정상 이미지에서 network 또는 discriminator를 학습한다. 학습 샘플 수 변화에 더 민감할 수 있다.
- **Prompt 기반 방법**: WinCLIP·AnomalyCLIP은 prompt·pretrained representation을 사용한다. AnomalyCLIP은 이번 framework에서 별도 checkpoint를 불러오므로 다른 정상 train 방법과 출발 조건이 완전히 같지 않다.

### 1.3 우리가 집중하는 접근과 남은 문제

- 이번 주의 초점은 새 모델 제안이 아니라 **공통 framework의 데이터 분할을 올바르게 만들고, 기존 209장 학습 결과와 비교 가능한 실행 evidence를 남기는 것**이다.
- 남은 문제: validation DataLoader는 만들었지만, 모든 trainer가 validation 결과로 epoch나 설정을 고르도록 연결되지는 않았다.

### 1.4 원인 가설

- 관찰한 limitation: 기존 loader의 validation 분할 부분이 주석 처리되어 있었고, `VAL` 경로가 train 정상 이미지와 올바르게 연결되지 않았다.
- **원인 가설 H1**: validation이 없으면 개발 중 모델/epoch/config 후보를 고를 때 test metric을 반복해서 보게 될 위험이 커진다. 우선 train 정상 이미지 일부를 분리하면 normal false positive를 점검할 독립 입력이 생긴다.
- H1이 맞더라도 normal-only validation만으로 실제 결함 탐지 성능을 완전히 선택할 수는 없다. 결함을 포함하는 선택 기준은 별도 설계가 필요하다.

### 1.5 이번 주 선택한 방향

- 선택: 정상 `train/good`만 seed 고정으로 90%/10%로 분리하고, 각 method를 기존 실행 조건과 최대한 같게 재실행한다.
- 선택 이유: 먼저 data split 자체가 올바르고, 방법들이 그 입력에서 실제로 실행되는지 확인해야 이후 validation 활용 정책을 논의할 수 있기 때문이다.

### 1.6 이번 주 기여 또는 검토 초점

- 핵심 판단: **현재 공통 framework는 test set을 바꾸지 않은 채 정상 train data에서 별도 validation loader를 만들 수 있고, 이 변경이 method별 결과에 미치는 영향을 실제 실행으로 측정하기 시작했다.**

## 2. 사전 지식과 문제 정의

### 기술 용어

- *TRAIN*: 모델이 정상 기준을 학습하는 이미지 집합이다.
- *VAL (validation)*: 학습에 넣지 않고 남겨 둔 검증 이미지 집합이다. 이번에는 정상 이미지만 있으며, 정상인데 높은 anomaly score가 나오는지 확인할 수 있다.
- *TEST*: 최종 성능 계산에만 쓰는 이미지 집합이다. `bottle` test는 정상 20장과 결함 63장이다.
- *anomaly score*: 이미지 한 장이 이상일 가능성을 나타내는 숫자다. Image AUROC 계산에 사용한다.
- *anomaly map*: 이미지의 각 위치가 이상일 가능성을 나타내는 2차원 점수 지도다. Pixel AUROC와 F1 계산에 사용한다.

### 표기법

| 표기법 | 설명 |
|---|---|
| `D_train` | 정상 학습 이미지 188장 |
| `D_val` | 학습에서 제외한 정상 validation 이미지 21장 |
| `D_test` | 정상 20장과 결함 63장으로 구성된 test 이미지 83장 |
| `f_m` | method `m`이 만드는 이상 탐지 모델 |
| `s_m(x)` | image `x`의 image anomaly score |
| `A_m(x)` | image `x`의 pixel anomaly map |

### 문제 정의

문제 1. **공통 framework에서 정상 validation 분할의 영향 확인**. MVTec AD `bottle`의 정상 train 이미지 209장이 주어졌을 때, seed 0으로 `D_train` 188장과 `D_val` 21장을 서로 겹치지 않게 만들고, test 83장을 바꾸지 않은 상태에서 각 방법 `f_m`을 실행한다. 출력은 test Image AUROC, Pixel AUROC, saliency F1 및 raw CSV다. 목표는 기존 209장 학습 결과와 비교 가능한 evidence를 남기는 것이다.

## 3. 관련 연구

### 3.1 현재 문제를 푸는 큰 연구 흐름

- PatchCore [1]는 정상 patch memory bank의 최근접 거리로 score/map을 만든다.
- PaDiM [2]는 정상 feature 분포의 확률적 차이로 score/map을 만든다.
- SimpleNet [3]은 정상 feature와 synthetic anomaly feature를 구분하는 discriminator를 학습한다.
- RD4AD [4]는 teacher feature와 decoder 복원 feature의 차이를 anomaly map으로 사용한다.

이 방법들은 정상 학습 이미지를 쓰지만, 필요한 정상 data 양과 학습 방식은 서로 다르다. 따라서 `bottle` 한 클래스, 한 seed의 209→188장 변화는 실행 진단이지 일반 성능 순위가 아니다.

### 3.2 현재 원인 가설에 대응하는 관련 연구

- One-Class AD 논문들은 정상 train data와 test data를 분리해 평가한다 [1-4].
- 이번 validation은 논문 방법 자체를 바꾸는 것이 아니라, framework 개발 과정에서 test set을 설정 선택에 쓰지 않도록 하는 protocol 보완이다.

### 3.3 이번 주 해결 후보 요약

- 후보 A: 정상 train 이미지 10%를 validation으로 분리한다.
  - 판단: **선택·구현 완료**.
  - 장점: test에 손대지 않고 정상 false positive를 점검할 data가 생긴다.
  - 한계: 정상만 있으므로 실제 결함 탐지 성능을 단독으로 최적화할 수 없다.

## 4. 선택한 방법 또는 절차

1. `datasets/base.py`에 seed를 보관한다.
2. `datasets/mvtec.py`에서 `TRAIN`과 `VAL`이 모두 `train/good`을 읽게 하고, seed와 category 이름으로 파일 순서를 고정해 188/21로 나눈다.
3. `main_dataset.py`에서 validation DataLoader에도 `train_val_split`을 전달한다.
4. `main.py`의 기본 `train_val_split`을 `0.9`로 설정한다. `1.0`을 지정하면 이전처럼 209장을 모두 학습에 사용한다.
5. `run_all_methods_bottle_validation_wsl.sh`로 method를 순차 실행한다. method·dataset·category·seed·각 method config는 기존과 같고, 학습 정상 이미지 수만 달라진다.

### 평가 지표

- Image AUROC: 정상/결함 이미지의 anomaly score 순위 분리 성능이다.
- Pixel AUROC: anomaly map이 결함 픽셀과 정상 픽셀을 분리하는 성능이다.
- Saliency F1: anomaly map을 이진화했을 때 정답 defect mask와의 겹침이다.

### 실험 1: validation split 동작 확인

#### 질문

- 정상 train의 10%를 남겨도 TRAIN·VAL·TEST가 겹치지 않는가?

#### 실제 결과

| split | 이미지 수 | 내용 |
|---|---:|---|
| TRAIN | 188 | `train/good`의 앞쪽 seed-고정 분할 |
| VAL | 21 | `train/good`의 나머지 seed-고정 분할 |
| TEST | 83 | 정상 20 + 실제 결함 63, 이전과 동일 |

- 자동 검사 결과: `TRAIN ∩ VAL = 0`, `VAL ∩ TEST = 0`.
- PatchCore smoke test도 188/21/83으로 DataLoader를 만들고 결과 CSV까지 생성했다.

#### 해석

- split 구현은 동작한다. 그러나 이 사실은 validation 점수로 model selection을 했다는 뜻은 아니다.
