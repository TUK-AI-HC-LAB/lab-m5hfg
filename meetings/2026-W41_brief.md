# 2026-W41 미팅 Brief - MuSc 공식 구현체와 공통 프레임워크 실행 비교

비교 대상은 **원논문 Table 17 공개값, 공식 MuSc 구현체의 자체 실행값, 공통 프레임워크 MuSc 실행값**이다. 논문 공개값과 이번 PC에서 측정한 값은 별도 열로 구분한다.

공통 프레임워크에 MuSc를 세 파일로 등록했고, **MVTec AD 15개 category, 총 1,725장**의 평가와 CSV 저장까지 완료했다. bottle은 기존 실행을 유지하고 나머지 14개를 같은 설정으로 실행했다. 공식 구현체 대비 15-category macro mean은 Image AUROC **-0.7519%p**, Pixel AUROC **+0.0718%p**다. 두 실행의 조건 차이는 설정 표에 기록했다. 차이의 원인을 분리하는 실험은 수행하지 않았다.

### 이번 주 변화

MuSc의 LNAMD·MSM·RsCIN을 trainer 내부에 구현하고, 사전학습 CLIP을 method가 직접 불러오도록 등록했다. batch는 특징 추출 단위이며, scoring은 동일 category의 전체 테스트 pool을 사용한다. 정상 TRAIN 188장과 VAL 21장은 공통 runner가 만들지만 MuSc의 학습·점수 계산에는 사용하지 않는다. bottle을 포함한 15개 category 모두 오류 없이 CSV를 생성했다. 이미지 1,725장의 해시·라벨·파일 순서가 공식 실행 당시와 같음을 별도 대조했다.

## 1. 서론

### 1.1 연구 배경과 중요성

공통 framework는 method 선택·데이터 입력·평가·저장을 연결한다. MuSc [1]는 정상 학습 자료 대신 라벨 없는 테스트 이미지의 상호 비교를 사용한다.

### 1.2 기존 접근의 큰 계열과 한계

MuSc는 라벨 없는 테스트 pool의 이미지들을 상호 비교한다. 이번 공통 구현도 category 전체 테스트 pool을 scoring에 사용하고 TRAIN/VAL은 사용하지 않는다.

### 1.3 우리가 집중하는 접근과 남은 문제

초점은 **MuSc의 전체 category pool scoring을 유지하면서 공통 입력·평가 경로로 통합했을 때, 기존 공식 실행과 어떤 차이가 나는가**다. 통합 후 실행 성공과 공식 구현체의 수치 재현은 구분해서 검증해야 한다.

### 1.4 원인 가설

미기재. 원인을 검증한 실험은 수행하지 않았다.

### 1.5 이번 주 선택한 방향

공통 framework의 dataset·전처리·평가·저장 경로를 유지한 채 MuSc를 등록하고, 공식 실행의 측정값과 대조했다.

### 1.6 이번 주 기여 또는 검토 초점

세 파일로 MuSc를 등록하고 15개 category의 전체 pool 실행을 완료했으며, 기존 공식 결과와 비교 가능한 지표와 비교할 수 없는 지표를 구분했다. 새로운 탐지 방법이나 성능 개선을 주장하는 단계는 아니다.

## 2. 사전 지식과 문제 정의

### 배경과 기술 용어

- **LNAMD** [1]: ViT stage의 패치 특징을 이웃 크기별로 집계한다. 이번 설정은 r=1, 3, 5다.
- **MSM** [1]: 각 query 패치와 다른 이미지의 최근접 패치 거리를 구하고, 이미지별 거리 중 낮은 30%를 평균한다. query 자신은 참조에서 제외한다.
- **RsCIN** [1]: CLIP의 class token 유사도로 이미지 점수를 보정한다. 이번 이웃 수는 1, 2, 3이다.
- **Transductive 평가**: 테스트 입력끼리 점수에 영향을 주는 평가다. 테스트 라벨과 마스크는 scoring에 사용하지 않고 최종 평가에만 사용한다.
- **Image / Pixel AUROC**: 각각 이미지 / 픽셀에서 정상과 이상 점수의 순위 구별 능력이다. 표에서는 0–1 값을 100배 한 %로 표시한다.
- **F1-max**: 여러 threshold에서 계산한 F1의 최대값이다. 공통 framework의 saliency CR F1은 정규화 후 threshold 0.5와 예측값 가중치를 사용하는 별도 계산이므로 동등한 지표가 아니다.

### 표기법

| 기호 | 설명 |
|---|---|
| D_u | bottle 테스트 pool, 정상 20장 + 이상 63장 |
| s_i / A_i | 이미지 i의 RsCIN 보정 점수 / 픽셀 이상 지도 |
| m_off / m_common | 공식 / 공통 실행에서 측정한 지표의 0–1 값 |
| Δ | 100 × (m_common − m_off), 단위 %p |


## 3. 관련 연구

### 3.1 현재 문제를 푸는 큰 연구 흐름

MuSc [1]는 라벨 없는 이미지 집합을 상호 비교한다. 이번 구현에서는 feature batch size와 category 전체 참조 pool을 별도로 사용했다.

### 3.2 공식·공통 구현에서 확인한 설정

공식 구현체의 CLIP transform, dataset mask transform, metric 계산을 직접 확인했다. 공식 이미지 입력은 CLIP transform의 bicubic resize·center crop·CLIP 정규화를 사용하고, 공통 입력은 square bilinear resize·ImageNet 정규화를 사용한다. 양쪽 mask 및 F1 정의도 다르다. 구현 근거는 [공식 repository](https://github.com/xrli-U/MuSc/tree/b76b93da8bd3096a99964a96ae29d46f197a0651)와 아래 실험 설정 표다.

### 3.3 이번 주 수행 범위

공통 입력·metric을 유지하고 MuSc를 등록했다. 공식 dataset·metric을 별도 경로로 추가하거나 동일 tensor·mask·metric으로 출력 대조를 수행하지 않았다.

## 4. 선택한 방법 또는 절차

`trainer/trainer_musc.py`에 특징 추출·LNAMD·MSM·RsCIN을 넣고, `configs/musc.yaml`에 method 기본 설정을 두며, `component_registry.py`에 `uses_backbone=False`로 등록했다. 기존 CLI에서는 `--method musc`를 선택한다. dataset·전처리·공통 metric·CSV 저장 코드는 변경하지 않았다.

특징은 batch별로 추출하되 scoring 전에 전체 category로 모은다. MSM의 reference-image chunk는 거리 행렬 메모리를 줄이는 계산 단위이며 참조 pool을 분할하지 않는다. shuffle·drop_last·여러 category 혼합·subtest는 완전한 category pool 조건과 맞지 않아 거부한다. TRAIN/VAL은 사용하지 않으며 optimizer 또는 fine-tuning도 없다.

## 5. 실험

### 비교 기준·데이터셋·평가 지표

직접 대조 범위는 15개 category 총 1,725장, seed 42의 category별 각 1회 실행이다. 아래 실험 1은 최초 bottle 통합 검증, 실험 2는 이후 15-category 확장 결과다. 공식 첫 bottle 실행과 공식 15-category 실행의 bottle 행은 동일한 metrics다. 전체 category 평균과 bottle 단일 값을 서로 비교하지 않았다. 공통 CSV의 min/max/mean이 같은 것은 한 번 평가했기 때문이며, 여러 seed 반복 평균이 아니다.

아래 `<...>`는 실행 환경의 경로로 바꿔야 하는 자리표시자다. 데이터와 checkpoint는 repository 밖에 둔다. 명령을 문서에 추가했으며 이번 보완 과정에서 실험을 재실행하지 않았다.

```bash
cd <common-framework-root>
<python> main.py --method musc --dataset mvtec --category <category> \
  --data-path <mvtec-root> --results-path <new-output-root> \
  --seed 42 --num-workers 1
```

### 실험 1: 공식 구현체와 공통 포팅의 bottle 결과

#### 비교 내용

공통 method 실행 경로의 MuSc 실행 완료 여부와 공식 실행 대비 AUROC 차이를 기록했다.

#### 설정

| 조건                      | 공식 구현체                                             | 공통 framework                                    |
| ----------------------- | -------------------------------------------------- | ----------------------------------------------- |
| 장비 / runtime            | RTX 5080, WSL2, Python 3.12.13, Torch 2.11.0+cu128 | 동일 PC·Python 환경                                 |
| 데이터                     | MVTec AD 원본 (repository 제외), bottle 전체 test 83장 | 같은 category·83장                                   |
| Backbone                | OpenAI pretrained ViT-L-14-336, 공식 open_clip       | 같은 모델 계열·가중치, 설치된 OpenAI CLIP 사용                |
| 해상도                     | 518×518                                            | 518×518                                         |
| Stage / r / MSM / RsCIN | block 6/12/18/24, r=1/3/5, 낮은 30%, k=1/2/3         | 동일 설정                                           |
| feature batch / pool    | 4 / 83                                             | 1 / 83                                          |
| 이미지 입력                  | bicubic resize + center crop + CLIP 정규화            | bilinear square resize + ImageNet 정규화, crop 미설정 |
| 정답 mask                 | 기본 bilinear resize → tensor → 최종 int32 변환          | nearest resize → tensor → 비영값 이진화               |
| map / metric            | raw map, sklearn AUROC·AP·F1-max·AUPRO             | 공통 map 정규화·GPU metric·saliency CR F1, PRO 미계산   |
| 모델 학습                   | 없음                                                 | 없음; 생성된 TRAIN 188 / VAL 21장은 사용하지 않음            |
| 정밀도                     | 공식 AMP 및 TF32 비활성화 기록                              | CUDA AMP 사용; 기존 공통 runtime 설정 유지                |

공식 설정의 feature_layers=[5,11,17,23]은 0-based로 저장되고 실제 추출 block은 +1이다. 공통 설정 [6,12,18,24]는 1-based다. 표의 backbone 일치는 동일 특징의 bitwise 일치를 뜻하지 않는다. 후속 데이터 검증에서 공통 loader의 1,725장 모두 공식 실행의 이미지별 SHA-256·라벨·파일 순서와 일치했다. 공통 raw prediction은 수집하지 않았다.

#### 재현 근거

- 공식 commit: `b76b93da8bd3096a99964a96ae29d46f197a0651`; [실행 wrapper](../method10/source/run_musc_local.py), [결과](../method10/source/results/bottle_paper_20261002/metrics.csv). 환경과 설정의 재현에 필요한 값은 본문에 고정했으며, 개인 경로가 담긴 실행 JSON은 공개하지 않는다.
- 공통 code: [trainer snapshot](../method10/source/common_framework_musc_snapshot/trainer/trainer_musc.py), [config snapshot](../method10/source/common_framework_musc_snapshot/configs/musc.yaml), [registry snapshot](../method10/source/common_framework_musc_snapshot/component_registry.py). 원 framework는 Git checkout이 아니므로 전체 source가 아니라 MuSc 관련 변경 파일 3개만 보존했다. [공개용 provenance](../method10/source/results/w41_official_vs_common_20261006/provenance_github.json)에 SHA-256을 기록했다. 이는 실행 시점의 불변 snapshot은 아니다.
- 공통 재실행 script: [run_musc_common_w41.sh](../method10/source/run_musc_common_w41.sh). 기존 결과를 덮어쓰지 않는 새 output 경로를 요구한다. 이번 비교 문서 작성 중 재실행한 것은 아니다.
- 원 실행 log와 외부 output CSV는 repository에 포함하지 않았다. GitHub에서 검토할 결과는 [공통 CSV](../method10/source/results/w41_official_vs_common_20261006/common_results_musc.csv)와 [공개용 provenance](../method10/source/results/w41_official_vs_common_20261006/provenance_github.json)에 남겼다.
- 비교 생성: [compare_musc_w41.py](../method10/source/compare_musc_w41.py); 실행 명령은 `<python> compare_musc_w41.py`이며, 필요한 결과 artifact는 위 repository-relative 경로에 둔다.

#### 해석

공통 bottle 실행의 CSV와 공식 실행 대비 AUROC 차이를 기록했다. 원인별 기여를 측정한 실험과 공통 raw score/map 기록은 없다.

### 실험 2: 15개 category 전체 비교

#### 비교 내용

15개 category의 공통 실행 완료 상태와 공식 실행 대비 category별·macro mean AUROC 차이를 기록했다.

#### 설정과 근거

실험 1과 같은 method 설정, seed 42, batch size 1, 해상도 518, CLIP·stage·r·MSM·RsCIN을 유지했다. bottle CSV를 재사용하고 나머지 14개는 category별 별도 CLI process로 실행했다. 총 test 1,725장이다. framework source는 실행 전·후 SHA-256이 동일했다. 데이터 audit는 공통 loader와 공식 실행 당시의 이미지 파일 해시·라벨·순서를 대조했고 15개 모두 통과했다. 이는 raw mask나 변환 후 tensor의 동등성을 뜻하지 않는다.

- commit: 공통 codebase는 Git checkout이 아님; [실행 전·후 source hash와 명령](../method10/source/results/w41_official_vs_common_all_20261006/execution_manifest_github.json).
- script: [전체 실행 runner](../method10/source/run_musc_common_all_w41.py), [비교 생성 코드](../method10/source/compare_musc_all_w41.py), [데이터 audit](../method10/source/audit_musc_common_data_w41.py).
- result: [공통 category metrics](../method10/source/results/w41_official_vs_common_all_20261006/common_category_metrics.csv), [공식 category metrics](../method10/source/results/mvtec_all_paper_20261002/category_metrics.csv), [category comparison](../method10/source/results/w41_official_vs_common_all_20261006/category_comparison.csv), [macro comparison](../method10/source/results/w41_official_vs_common_all_20261006/macro_comparison.csv).
- status/log: [공개용 실행 manifest](../method10/source/results/w41_official_vs_common_all_20261006/execution_manifest_github.json). 원 WSL log와 외부 output CSV는 repository에 포함하지 않았고, bottle은 기존 결과를 재사용했다.
- dataset identity: [검증 CSV](../method10/source/results/w41_official_vs_common_all_20261006/dataset_identity.csv).

절댓값 기준 가장 큰 Image AUROC 변화는 **screw (-3.8738%p)**, Pixel AUROC 변화는 **cable (+1.1675%p)**다.
