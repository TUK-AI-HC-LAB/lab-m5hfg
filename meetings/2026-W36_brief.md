## 1. 서론

### 1.1 연구 배경과 중요성

- Vision anomaly detection은 이미지 전체의 이상 유무와 이상 위치를 찾는 문제임.
- 실제 검사에서는 새 제품 범주가 생길 때마다 그 범주의 이상 label을 충분히 모으기 어려움. 따라서 target domain을 거의 또는 전혀 보지 않고 적용하는 zero-shot·few-shot 설정이 중요함.
- 다만 `zero-shot`이라는 이름만으로 학습 조건이 같아지지는 않음. source domain의 anomaly label로 학습했는지, target domain의 정상 이미지를 reference로 봤는지를 함께 적어야 성능 수치를 공정하게 읽을 수 있음.

### 1.2 비교 기준: target test data와 source·target domain

- **target domain**: 최종 이상 점수와 anomaly map을 계산할 대상. 예: VisA의 `candle`.
- **source domain**: target에 적용하기 전에 prompt 또는 adapter를 학습하는 데 쓰는 별도 데이터. 예: MVTec AD.
- **full-shot**: target인 `candle`의 많은 데이터를 학습에 사용하고, 같은 `candle` 범주를 추론하는 설정.
- **few-shot / few-normal-shot**: target인 `candle`의 정상 이미지 몇 장을 학습 또는 normal reference로 사용하고, 같은 `candle`을 추론하는 설정.
- **zero-shot**: target인 `candle`의 이미지나 normal reference를 학습·참조에 사용하지 않고 바로 `candle`을 추론하는 설정. 단, source domain으로 학습했는지는 별도로 밝혀야 함.

### 1.3 세 방법의 target data 사용 방식

- **AnomalyCLIP [1]**: source domain의 anomaly 관련 데이터로 object-agnostic prompt를 학습하고, target domain은 학습·reference 없이 추론함. 예: MVTec AD → VisA, 또는 VisA → MVTec AD.
- **WinCLIP [2]**: zero-shot WinCLIP은 CLIP과 수작업 prompt를 그대로 사용하며, 별도 source anomaly dataset 학습과 target normal reference를 사용하지 않음. few-normal-shot WinCLIP+는 target domain의 정상 이미지 몇 장을 normal reference로 사용함.
- **AA-CLIP [3]**: source domain의 image-level label과 pixel mask로 text·visual residual adapter를 학습하고, target domain은 학습·reference 없이 추론함. 이 저장소의 기존 조사 예는 VisA → MVTec AD임.

### 1.4 같은 zero-shot으로 직접 비교하기 어려운 이유

- AnomalyCLIP과 AA-CLIP은 target에는 zero-shot이지만, source domain의 anomaly supervision을 사용해 prompt 또는 adapter를 학습함.
- WinCLIP zero-shot은 추가 anomaly dataset 학습 없이 pretrained CLIP과 text prompt로 바로 추론함. 따라서 source supervision을 쓴 두 방법과 성능 차이를 모델 구조만의 차이로 해석할 수 없음.
- WinCLIP+는 target normal reference를 사용하므로 WinCLIP zero-shot, AnomalyCLIP, AA-CLIP의 target zero-shot 결과와 다른 protocol임.

### 1.5 원인 가설

- H1: 세 방법의 성능 차이 일부는 모델 구조뿐 아니라 source supervision과 target normal reference 사용 여부의 차이에서 발생함.
- H1이 맞다면, 비교표에 target data 사용 방식과 source·target 방향을 함께 적었을 때 직접 비교 가능한 결과와 불가능한 결과가 구분됨.

### 1.6 이번 주 선택한 방향

- AnomalyCLIP, WinCLIP, AA-CLIP을 모두 `source로 학습했는가`, `target normal reference를 썼는가`, `target test data만 추론에 썼는가`의 세 항목으로 조사함.
- 이 기준을 먼저 고정한 뒤 prompt, adapter, window feature 같은 방법 구조의 유사점·차이점을 비교함.

### 1.7 이번 주 기여 또는 검토 초점

- 이번 주의 핵심은 세 방법의 우열을 정하는 것이 아니라, 각 수치가 어떤 학습 정보 조건에서 나온 것인지 명확히 구분하는 것임.

## 3. 관련 연구

### 3.1 AnomalyCLIP

- **무엇을 푸는 방법인가**: 보지 못한 target domain에서 이미지 이상 여부와 이상 위치를 찾는 zero-shot anomaly detection 방법임 [1].
- **출발점**: 일반 CLIP은 물체의 종류를 구분하는 의미에 더 민감하여, 정상·이상 자체를 구분하는 데는 약할 수 있음 [1].
- **핵심 아이디어**: 물체 이름에 묶이지 않는 object-agnostic normal prompt와 abnormal prompt를 학습함. 즉, `candle`이나 `bottle`이라는 물체 이름보다 정상성·이상성이라는 공통 신호를 텍스트 표현에 담으려는 방식임 [1].

![사용자 제작 AnomalyCLIP 구조도](images/AnomalyCLIP_structure.png)

*그림 1. 사용자 제작 AnomalyCLIP 구조도. 학습 가능한 정상·이상 text prompt, 고정 CLIP text/vision encoder, global·local visual feature, cosine similarity 기반 이상 점수 흐름을 요약함.*

- **학습 방식**: CLIP `ViT-L/14@336px` backbone은 고정하고, auxiliary source domain으로 learnable text prompt를 학습함. 학습에는 이미지 전체의 정상·이상 구분과 patch 수준 위치 구분을 함께 쓰는 global-local abnormality loss를 사용함 [1].
- **추론 방식**: target 이미지의 global feature와 abnormal text embedding의 유사도로 image-level anomaly score를 만들고, local feature와 두 prompt의 유사도로 pixel-level anomaly map을 만듦 [1].
- **source / target 예시**: target이 VisA이면 MVTec AD로 prompt를 학습한 뒤 VisA를 추론함. 반대로 target이 MVTec AD이면 VisA로 prompt를 학습한 뒤 MVTec AD를 추론함 [1].
- **test data 기준**: target domain 이미지는 prompt 학습이나 normal reference로 사용하지 않음. 따라서 target 기준 zero-shot임. 단, source domain의 anomaly 관련 데이터로 prompt를 학습하므로 학습 없이 바로 쓰는 zero-shot CLIP과는 구분해야 함.
- **강점**: 특정 물체 이름 없이도 여러 target domain에 적용할 수 있고, image-level 판별과 pixel-level 위치 추정을 함께 제공함.
- **비교 시 주의점**: AnomalyCLIP의 성능은 source domain의 종류와 학습 데이터에 영향을 받을 수 있으므로, target에 직접 학습한 full-shot 방법이나 target normal image를 참조하는 few-shot 방법과 같은 조건의 수치로 해석하면 안 됨.

## 8. 이번 주 주요 질문 1개

- 질문: 세 방법을 비교할 때 target domain의 학습·참조 여부를 어떤 기준으로 같은 protocol 또는 다른 protocol으로 구분할 것인가?
- 내가 현재 판단한 답: target domain data를 adapter·model 학습에 사용했는지, 정상 reference로 사용했는지, 전혀 보지 않았는지를 분리해 기록해야 함.
- 그 판단의 근거: full-shot·few-shot·zero-shot은 target domain data를 언제 어떤 목적으로 썼는지가 다름.
- 왜 이 판단이 틀렸을 수 있는가: 논문마다 zero-shot이라는 용어의 세부 정의나 source/target 방향이 다를 수 있음.
- 교수님이 판단해주면 다음 주 무엇이 바뀌는가: 비교표의 분류 기준과 다음 논문 조사 범위를 확정함.
