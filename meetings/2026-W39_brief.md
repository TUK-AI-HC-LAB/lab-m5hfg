### 이번 주 변화

- 공통 한계를 `target 정상 data 사용 여부`가 아니라 **target 고유의 정상·결함 경계를 직접 관찰했는가**로 다시 정의함.
- One-Class AD는 target 정상 이미지를 쓰지만 target 결함은 보지 않음. Zero-shot AD는 target 정상·결함을 모두 보지 않고 source·text·synthetic 기준을 사용함.
- 따라서 target의 정상 모양이 source에서 배운 결함과 비슷하거나, target의 실제 결함이 기존 이상 기준과 다르면 오탐·누락이 생길 수 있다는 H1을 세움.
- FAPrompt를 조사하여, coarse한 이상 prompt를 query별 prior로 조정하는 target-free 개선 후보를 확보함 [8].

### 현재 연구 단계

- 현재 phase: **Phase 3 - Limitation Identification (초기)**.
- 이 phase라고 판단한 이유: 방법별 기준 상태와 기존 실행 결과를 연결해 공통 limitation 후보와 반증 가능한 H1을 다시 정함.
- 다음 phase로 가기 위해 필요한 evidence: target 정상 모양과 source 이상 의미가 겹친 실제 오탐 사례, target 실제 결함과 기존 이상 기준이 어긋난 실제 누락 사례, 이를 줄이는 통제 조건.

## 1. 서론

### 1.1 연구 배경과 중요성

- Vision anomaly detection은 제품 이미지에서 불량 여부와 위치를 찾는 문제임.
- 실제 현장에서는 target 제품의 모든 결함 유형을 미리 모으기 어렵기 때문에, 정상 이미지만 쓰는 One-Class AD와 target 학습 이미지를 쓰지 않는 zero-shot AD가 중요함 [1-7].
- 그러나 실제 target에서 `정상인 모양`과 `결함인 모양`의 경계가 기존 data에서 배운 경계와 다르면, anomaly score가 잘못 높거나 낮아질 수 있음.

### 1.2 기존 접근의 큰 계열과 한계

- **One-Class AD**: target 정상 이미지에서 정상 기준을 만듦. PatchCore는 normal memory 거리 [1], SimpleNet은 정상 특징과 synthetic feature로 학습한 판별기 [2], RD4AD는 teacher-student 복원 차이 [3]를 사용함.
  - 장점: target 정상 모양을 직접 반영함.
  - 한계: target 실제 결함을 학습하지 않으므로, 결함 여부는 저장한 정상 기준에서 얼마나 벗어났는지로만 판단함.
- **Zero-shot AD**: AnomalyCLIP·AA-CLIP은 source 기반 prompt·adapter [4, 6], WinCLIP은 prompt ensemble [5], AnomalyVFM은 synthetic normal/anomaly data [7]로 기준을 만듦.
  - 장점: target 학습 데이터 없이 적용 가능함.
  - 한계: source 또는 synthetic data의 결함 의미가 target 정상 모양과 겹치거나, target 실제 결함을 충분히 대표하지 못할 수 있음.

### 1.3 우리가 집중하는 접근과 남은 문제

- 이번 주에는 특정 방법의 평균 성능이 아니라, **target 고유 정상·결함 경계를 직접 보지 못하는 조건**을 공통 비교 축으로 사용함.
- 모든 방법은 target 실제 결함을 직접 정답으로 학습하지 않으므로, 처음 보는 target 결함이 기존 기준에서 정상과 충분히 구별되지 않으면 누락될 수 있음.
- 특히 zero-shot 방법에서는 target 정상 모양이 source에서 배운 결함 특징과 비슷할 때 정상인데도 높은 anomaly score가 나오는 오탐이 추가로 생길 수 있음.

### 1.4 원인 가설

- 현재 limitation: target 고유의 정상·결함 경계가 직접 supervision되지 않음.
- **원인 가설 H1**: target 실제 결함을 학습하지 않은 기준 상태에서는 처음 보는 결함이 정상 기준과 충분히 구별되지 않아 누락될 수 있음. zero-shot 방법에서는 source 이상 특징과 target 정상 모양의 겹침으로 오탐도 생길 수 있음.
- H1이 그럴듯한 이유: One-Class AD는 normal-only boundary를, zero-shot AD는 source·text·synthetic boundary를 사용함. 어느 경우도 target의 실제 정상·결함 쌍을 직접 학습하지 않음.
- H1이 맞다면 관찰되어야 하는 현상: anomaly map에서 정상 영역이 강하게 반응하는 오탐 또는 정답 결함 mask 안의 약한 반응이 나타나야 함.

### 1.5 이번 주 선택한 방향

- 이번 주 선택: target 고유 경계가 겹치거나 어긋난 사례를 input·ground-truth mask·anomaly map으로 먼저 확인함.
- 선택 이유: 평균 AUROC만으로는 target 정상과 source 이상 특징이 실제로 겹쳤는지 판단할 수 없음.
- H1 검증 방법: 같은 category·split에서 정상 오탐, 결함 누락을 유형별로 기록하고, One-Class·zero-shot의 기준 상태와 연결함.

### 1.6 이번 주 기여 또는 검토 초점

- 핵심 판단: **target data 사용 여부는 방법군 차이이고, target 고유 정상·결함 경계를 직접 보지 못하는 문제는 모든 방법에서 확인할 수 있는 공통 limitation 후보임.**
- evidence 위치: `## 3`, `## 5`, W31·W34·W37·W38 실행 결과와 FAPrompt 관련 연구 노트.

## 2. 사전 지식과 문제 정의

### 기술 용어

- *target domain*: 실제로 판별할 제품 또는 데이터셋.
- *source domain*: target 평가 전에 adapter·prompt·기준을 만드는 데 사용한 보조 데이터셋.
- *정상·결함 경계*: feature 또는 score 공간에서 target 정상과 target 결함을 나누는 기준.
- *오탐*: 정상 영역 또는 정상 이미지를 이상으로 판단함.
- *누락*: 실제 결함 영역 또는 결함 이미지를 정상에 가깝게 판단함.
- *Pixel AUROC*: anomaly map이 정답 결함 mask와 pixel 단위로 얼마나 잘 분리되는지 나타내는 지표. 높을수록 좋음.

### 표기법

| 표기법 | 설명 |
|---|---|
| `D_t^N` | target 정상 이미지 집합 |
| `D_t^A` | target 실제 결함 이미지 집합. One-Class·zero-shot 기준 학습에는 사용하지 않음 |
| `c` | 정상·이상 판단을 위한 기존 기준 상태 |
| `s(x)` | test image `x`의 image 또는 pixel anomaly score |

### 문제 정의

문제 1. 기존 방법의 기준 상태 `c`와 target test image가 주어졌을 때, 우리의 과제는 `D_t^N`과 `D_t^A`의 경계가 기존 기준에서 겹치거나 어긋난 사례를 찾아 H1을 검증하는 것임. 성공 기준은 input·mask·anomaly map과 raw score를 함께 남겨, 오탐과 누락을 실제 위치 수준에서 확인하는 것임.

## 3. 관련 연구

### 3.1 기준 상태를 만드는 연구 흐름

- PatchCore [1], SimpleNet [2], RD4AD [3]은 target 정상 이미지에서 기준을 만듦. 정상 경계를 직접 학습하지만 target 결함을 직접 보지 않음.
- AnomalyCLIP [4], WinCLIP [5], AA-CLIP [6], AnomalyVFM [7]은 target 실제 결함 대신 source·prompt·synthetic data로 이상 기준을 만듦. target-free 적용은 가능하지만 target 정상과 source 이상 의미의 겹침을 별도로 확인해야 함.

### 3.2 H1에 대응하는 관련 연구

- AnomalyCLIP 실행에서는 `cable`의 Image AUROC 69.5%, `transistor`의 Pixel AUROC 70.5%가 평균보다 낮았음. 현재 수치만으로는 원인을 확정할 수 없으나, category별 normal-defect boundary를 map으로 확인할 필요가 있음을 보여 줌 (`meetings/2026-W37_brief.md`).
- RD4AD 실행에서는 `transistor`의 Pixel AUROC 92.30%, AU-PRO 78.30%가 전체 평균보다 낮았음. 원 논문은 annotation 불일치와 context 관계 부족을 후보 원인으로 제시함 (`meetings/2026-W34_brief.md`).
- FAPrompt [8]는 coarse abnormal prompt가 diverse target 결함을 놓칠 수 있다고 보고, multiple fine-grained abnormal prompt와 query별 abnormality prior로 기준을 조정함. 이는 target 실제 결함 label 없이도 H1을 완화할 후보임.

### 3.3 이번 주 해결 후보 요약

- 후보 A: 정상·결함의 경계가 애매한 실제 사례를 먼저 진단함.
  - 근거: W34·W37의 낮은 위치 지표와 현재 map artifact 부족.
  - 가능성: H1의 오탐·누락을 모듈 변경 없이 확인할 수 있음.
  - 판단: **선택**.
- 후보 B: FAPrompt처럼 query별 prior로 이상 기준을 세밀하게 조정함 [8].
  - 가능성: target 결함 label 없이 static abnormal prompt의 의미를 보정할 수 있음.
  - 실패 가능성: query의 정상 texture를 이상 prior로 오인할 수 있음.
  - 판단: **보류**. H1 사례를 확인한 뒤 구현 후보로 검토함.

## 4. 선택한 방법 또는 절차

- 선택한 절차: 동일 category·split에서 input, ground-truth mask, anomaly map, image/pixel score를 함께 저장하고 정상 오탐·결함 누락을 분류함.
- 비교 대상: PatchCore normal memory, RD4AD 복원 차이, AnomalyCLIP·WinCLIP·AA-CLIP의 visual-text 기준, AnomalyVFM decoder score.
- protocol: 먼저 이미 map이 저장된 PatchCore·AnomalyCLIP 사례를 확인하고, RD4AD·WinCLIP도 동일 형식의 map 저장을 추가함.
- H1 검증: target 결함이 정상 기준과 충분히 구별되지 않아 누락되는지, zero-shot에서 target 정상 영역이 source·synthetic 이상 기준과 닮아 오탐되는지를 mask와 함께 확인함.

## 5. 실험

### 비교 기준

- 평균 AUROC만으로 H1을 판단하지 않음.
- 하나의 test image에서 input, ground-truth mask, anomaly map, image/pixel score가 함께 있어야 함.
- 정상 영역의 높은 score는 오탐 후보, mask 내부의 낮은 score는 누락 후보로 기록함.

### 평가 지표

- Image AUROC: 이미지 단위 정상·결함 분리 성능.
- Pixel AUROC와 AU-PRO: 결함 위치 분리 성능.
- 정성 사례: 정상 모양과 결함 모양이 기준 상태와 어떻게 겹치거나 어긋나는지 확인함.

| 논문이 지적한 문제 | 바꾼 부분 | 논문 보고 결과 | 현재 H1과의 연결 |
|---|---|---|---|
| coarse abnormal prompt가 다양한 세부 결함을 놓칠 수 있음 | multiple fine-grained abnormal prompt와 query별 abnormality prior [8] | 산업 데이터에서 기존 최고 비교 방법 대비 최대 Image AUROC +3.9%p, AP +3.0%p | target 실제 결함 label 없이 기준 상태를 더 세밀하게 만드는 후보 |

- 해석: FAPrompt는 H1의 직접 증거가 아니라, H1 사례가 확인됐을 때 비교할 target-free 개선 후보임.
