### 이번 주 변화

- zero-shot AD의 한계를 `target 제품의 정상 모양을 보지 못해 정상 영역을 이상으로 오인할 수 있음`으로 구체화함.
- 실제 제조 환경에서는 양산 전 정상 시제품을 만들 수 있다는 점에 주목함.
- 따라서 새 방향을 **소수의 정상 시제품을 few-shot reference로 사용하여 zero-shot 기준을 target에 맞추고, 필요한 최소 reference 수를 확인하는 것**으로 정함.
- 이 방향은 few-shot이 항상 더 좋다는 결론이 아니라, 시제품 reference가 정상 오탐을 실제로 줄이는지 검증할 가설임.

### 현재 연구 단계

- 현재 phase: **Phase 3 - Limitation Identification (초기)**.
- 이 phase라고 판단한 이유: 기존 WinCLIP 0/1/2/4-shot 결과에서 target 정상 reference 추가와 성능 향상의 관계를 확인했고, 이제 그 성능 변화의 원인을 image-level failure로 진단해야 함.

## 1. 서론

### 1.1 연구 배경과 중요성

- Vision anomaly detection은 제품 이미지에서 불량 여부와 위치를 찾는 문제임.
- 실제 현장에서는 모든 결함 유형을 미리 모으기 어려워, target 결함 label 없이 동작하는 One-Class AD와 zero-shot AD가 중요함 [1-7].
- 특히 신규 제품은 양산 전부터 검사 기준이 필요하지만, zero-shot AD는 target 제품의 정상 외관을 보지 못한 채 source·text·synthetic 기준으로 판단함.

### 1.2 기존 접근의 큰 계열과 한계

- **One-Class AD**: target 정상 이미지로 정상 기준을 만듦. PatchCore는 normal memory 거리 [1], SimpleNet은 정상 특징과 synthetic feature로 학습한 판별기 [2], RD4AD는 teacher-student 복원 차이 [3]를 사용함.
  - 장점: target 정상 외관을 직접 기준에 반영함.
  - 한계: target 정상 이미지 집합을 준비해야 함.
- **Zero-shot AD**: target 학습 이미지 없이 source·prompt·synthetic data로 기준을 만듦. AnomalyCLIP·AA-CLIP은 source 기반 prompt·adapter [4, 6], WinCLIP은 prompt ensemble [5], AnomalyVFM은 synthetic normal/anomaly data [7]를 사용함.
  - 장점: target 데이터 없이 즉시 적용 가능함.
  - 한계: target 고유의 정상 모양이 기존 이상 기준과 겹치면 정상 영역을 이상으로 판단할 수 있음.

### 1.3 우리가 집중하는 접근과 남은 문제

- 이번 주에 집중하는 접근은 pure zero-shot을 포기하는 것이 아니라, **양산 전 정상 시제품 몇 장을 few-shot reference로 추가하는 것**임.
- 제조 과정에서는 제품을 본격적으로 생산하기 전에 시제품을 만들 수 있고, 실제 검사는 카메라 각도·조명·제품 위치를 고정한 조건에서 수행한다고 가정함.
- 이 환경에서는 여러 정상 시제품의 차이가 크지 않을 수 있으므로, 어떤 reference를 골라야 하는가보다 **정상 시제품이 최소 몇 장이면 충분한가**가 우선 질문임.
- 남은 문제는 1장의 시제품 reference가 이미 충분한지, 여러 장이 정상 오탐을 더 줄이는지, 또는 실제 결함까지 정상으로 만들어 누락을 늘리는지 알 수 없다는 점임.

### 1.4 원인 가설

- 현재 limitation: zero-shot 기준은 target 제품의 정상 모양을 직접 관찰하지 않음.
- **원인 가설 H1**: source·text·synthetic 기준만 사용하는 0-shot detector는 target 정상 영역을 이상 특징으로 오인해 오탐할 수 있음. 정상 시제품을 few-shot reference로 넣으면 이 오탐은 줄어들 수 있음.
- H1이 그럴듯한 이유: target 정상 reference를 쓰는 One-Class AD와 WinCLIP few-shot 조건은 target 외관 정보를 기준에 추가하며, pure zero-shot은 이를 사용하지 않음 [1, 5].
- H1이 맞다면 관찰되어야 하는 현상: 같은 test image에서 0-shot map의 밝은 정상 영역이 1-shot map에서 낮아지고, 2/4-shot에서 성능이 더 오르는지 또는 포화되는지 확인되어야 함. 정답 결함 mask 내부의 반응은 유지되거나 높아져야 함.

### 1.5 이번 주 선택한 방향

- 이번 주 선택: 정상 시제품 few-shot reference의 **최소 충분 개수**를 확인하는 방향을 선택함.
- 선택 이유: 촬영 조건이 고정된 제조 환경에서는 reference 선택이나 복잡한 통합 알고리즘보다, 1장의 시제품이 충분한지와 성능 포화점을 먼저 아는 것이 실용적임. 기존 WinCLIP+ 1/2/4-shot 결과가 0-shot보다 높은 위치 지표를 보였음.
- 다음 주 계획: 최신 zero-shot AD 논문까지 조사하여, 공식 구현체가 있고 target normal reference 없이 높은 성능을 보고한 후보를 선정함. 그 뒤 선정 모델을 동일 target·동일 zero-shot protocol에서 확인하고, 정상 시제품 1/2/4장을 few-shot reference로 추가해 AUROC와 query별 map 변화를 확인함.

### 1.6 이번 주 기여 또는 검토 초점

- 핵심 판단: **새 제품의 양산 전 정상 시제품은 zero-shot AD의 기준을 target에 맞추는 현실적인 few-shot 정보이며, WinCLIP+ 결과는 1~4장의 reference가 성능을 높일 수 있음을 정량적으로 지지함.**
- 단, 현재 결과만으로 성능 상승의 원인을 정상 오탐 감소라고 확정하지 않음. 이를 확인하려면 0/1/2/4-shot map 비교가 필요함.

## 2. 사전 지식과 문제 정의

### 기술 용어

- *target domain*: 실제로 검사할 신규 제품 또는 데이터셋.
- *zero-shot*: target 정상·결함 이미지를 기준 생성 또는 학습에 사용하지 않고 추론함.
- *few-shot normal reference*: target 정상 이미지를 매우 적은 수(예: 1/2/4장)만 기준 생성 또는 보정에 사용함. 이번 환경에서는 촬영 조건이 고정되어 reference 간 차이가 작다고 가정함.
- *시제품*: 양산 전에 제작한 정상 제품. 이 연구에서는 label이 없는 target 정상 few-shot reference로 사용함.
- *오탐*: 정상 이미지 또는 정상 영역을 이상으로 판단함.
- *누락*: 실제 결함 이미지 또는 결함 영역을 정상에 가깝게 판단함.

### 표기법

| 표기법 | 설명 |
|---|---|
| `D_t^N` | target 정상 이미지 집합 |
| `R_k` | `D_t^N`에서 고른 정상 시제품 `k`장 reference 집합 |
| `x` | target test image |
| `s_k(x)` | `R_k`를 사용한 image 또는 pixel anomaly score |

### 문제 정의

문제 1. **시제품 few-shot의 최소 충분 개수 찾기**. target test image `x`와 양산 전 정상 시제품 reference `R_k`가 주어졌을 때, 우리의 과제는 촬영 조건이 고정된 환경에서 `k=0,1,2,4` 중 정상 오탐을 줄이면서 실제 결함 위치를 유지하는 가장 작은 `k`를 찾는 것임. 성공 기준은 동일 test set에서 normal false positive가 줄고, Pixel AUROC·AU-PRO 및 결함 mask 내부 반응이 유지 또는 개선되는 것임.

## 3. 관련 연구

### 3.1 기준 상태를 만드는 연구 흐름

- PatchCore [1], SimpleNet [2], RD4AD [3]은 target 정상 이미지에서 기준을 만듦. 이는 target 외관을 반영하지만 many-normal-image 설정임.
- AnomalyCLIP [4], AA-CLIP [6], AnomalyVFM [7]은 target을 보지 않고 source·prompt·synthetic data로 기준을 만듦. 즉시 적용할 수 있지만 target 정상 외관의 오탐 위험을 별도로 확인해야 함.
- WinCLIP [5]은 pure zero-shot과 target 정상 reference를 쓰는 few-shot 확장을 구분함. 따라서 시제품 few-shot 비교를 설계할 직접적인 출발점임.

### 3.2 H1에 대응하는 관련 연구

- WinCLIP [5]은 target 정상 reference image를 query와 비교하는 few-shot 조건을 제시함. 이는 소수의 정상 시제품을 검사 기준에 넣는 방향과 가장 직접적으로 연결됨.
- 현재 WinCLIP 실행에서 WinCLIP+는 0-shot보다 두 target에서 모두 높은 위치 지표를 보였음. MVTec AD에서는 Pixel AUROC 82.3%→94.2%, AU-PRO 61.9%→85.4%, Image AUROC 90.4%→95.3%였고, VisA에서는 73.2%→95.2%, 51.0%→81.4%, 75.5%→84.1%였음(각각 0-shot→4-shot, `method7/source/results/winclip_target_comparison.csv`). 이는 few-shot reference 방향의 실제 evidence임. 다만 상승 원인이 정상 오탐 감소인지 결함 반응 증가인지는 map으로 아직 분리하지 못함.

### 3.3 이번 주 해결 후보 요약

- 후보 A: 정상 시제품 few-shot reference의 최소 충분 개수를 확인함.
  - 관련 연구 근거: WinCLIP few-shot [5].
  - 가능성: target 정상 외관을 직접 제공해 정상 오탐을 줄이고, 1-shot으로 충분한지 또는 추가 시제품이 필요한지 판단할 수 있음.
  - 실패 가능성: reference 수가 늘어도 성능이 오르지 않거나, 결함 누락이 함께 늘 수 있음.
  - 판단: **선택**.

## 4. 선택한 방법 또는 절차

- 선택한 절차: 이미 실행한 WinCLIP `R_0`, WinCLIP+ `R_1`, `R_2`, `R_4` 결과를 정량 evidence로 사용하고, 다음으로 각 조건의 map을 비교함.
- 기준 모델 선정: WinCLIP은 0/1/2/4-shot 결과가 있어 시제품 few-shot의 가능성을 보여 주는 evidence로 사용함. 다음 주에는 현재 구현한 방법에 한정하지 않고, 최신 zero-shot AD 논문을 조사함. 그중 **공식 구현체가 있고, target normal reference 없이 높은 성능을 보고했으며, MVTec AD 또는 VisA에서 평가 가능한 후보**를 선정해 동일 target·동일 protocol으로 확인함.
- 통제 조건: target category, test split, backbone, prompt, 전처리, seed를 고정하고 reference 수만 바꿈. reference 선택 알고리즘은 새로 제안하지 않고 기존 WinCLIP+ 방식을 그대로 사용함.
- 비교 출력: Image AUROC, Pixel AUROC, AU-PRO, 정상 오탐 사례 map, 결함 누락 사례 map.
- 다른 방법과의 연결: PatchCore·SimpleNet·RD4AD는 many-normal-image One-Class 기준선으로 유지함. AnomalyCLIP·WinCLIP·AA-CLIP·AnomalyVFM 중 선정된 zero-shot 모델을 정상 시제품 few-shot 조건으로 확장함.

## 5. 실험

### 비교 기준

- 0-shot과 few-shot을 같은 protocol으로 섞어 평균 성능만 비교하지 않음.
- 같은 category·test image에서 input, ground-truth mask, anomaly score map을 함께 확인함.
- 정상 mask 밖의 높은 점수는 오탐 후보, 결함 mask 내부의 낮은 점수는 누락 후보로 기록함.

### 평가 지표

- Image AUROC: 이미지 단위 정상·결함 분리 성능.
- Pixel AUROC와 AU-PRO: 결함 위치 분리 성능.
- 정성 사례: 0-shot 대비 few-shot에서 정상 오탐과 결함 누락 위치가 어떻게 바뀌는지 확인함.

#### 설정

- 현재 확보한 map: PatchCore의 bottle·pill·transistor 결과 패널, RD4AD transistor score map, AnomalyCLIP bottle·pill·transistor score map.
- 비교 폴더: `meetings/2026-W39_h1_comparison/ground_truth_masks/`, `meetings/2026-W39_h1_comparison/anomaly_score_maps/`.

#### 해석과 다음 실행

- WinCLIP+의 정량 상승은 시제품 few-shot 방향을 지지하는 실제 evidence임. MVTec AD에서는 1-shot부터 위치 지표가 크게 상승했고, 4-shot이 현재 가장 높은 수치임.
- 하지만 H1의 세부 원인인 `target 정상 오탐 감소`는 아직 증명되지 않음.
- 다음 주 실행은 세 단계임. 먼저 최신 zero-shot AD 논문을 조사해 후보를 넓게 수집함. 다음으로 공식 구현체·target-free 조건·보고 성능·평가 가능성을 기준으로 하나를 선정하고 동일 target·동일 protocol에서 기준선을 확인함. 마지막으로 선정 모델의 `R_0`, `R_1`, `R_2`, `R_4` 조건에서 같은 query ID의 map을 저장함. 정상 오탐, 결함 누락, 정상 검출 사례를 같은 query ID로 기록함.

## 6. 논의

### 6.1 연구 방향

> 최신 zero-shot AD 모델을 하나 선정하고, 양산 전 정상 시제품을 few-shot reference로 추가해 성능 변화를 분석하는 방향이 적절한가?

- 현재 판단: 적절함. WinCLIP+의 1/2/4-shot 결과는 target 정상 reference가 zero-shot 기준을 보완할 가능성을 보여 줌.
- 확인할 점: 먼저 선정 모델의 pure zero-shot 기준선과 구현체 재현성을 확인한 뒤 few-shot 변형을 적용해야 함.

### 6.2 차별점 기준

> 단순히 few-shot reference를 추가하는 것을 넘어, 어떤 분석 또는 방법적 차별점까지 있어야 연구 방향으로 타당한가?

- 현재 판단: 최소 충분 reference 수, shot 수에 따른 성능 포화, 정상 오탐·결함 누락 변화의 분석을 우선 수행함.
- 확인할 점: 이 분석만으로 충분한지, 또는 시제품 few-shot을 반영하는 추가 score 보정·reference 활용 방법이 필요한지 판단받음.

## 8. 이번 주 주요 질문 1개

- 질문: 현재 구현한 방법에 한정하지 않고 최신 zero-shot AD 논문을 조사해 하나를 선정한 뒤, 해당 공식 구현체에 정상 시제품 few-shot reference를 추가하는 변형을 시도해도 되는가?
- 내가 현재 판단한 답: 가능함. 단, 논문 선정 시 official code, pure zero-shot 조건, target dataset 평가 가능성, 보고 성능을 함께 확인하고, 선정 뒤에는 pure zero-shot 기준선 성능과 구현체의 재현성을 확인해야 함. few-shot 변형에서는 reference 수만 `0/1/2/4`로 바꿈.
- 그 판단의 근거: 기존 WinCLIP+는 target 정상 reference를 추가했을 때 WinCLIP 0-shot보다 MVTec AD와 VisA에서 위치·이미지 지표가 높았음 (`method7/source/results/winclip_target_comparison.csv`).
- 왜 이 판단이 틀렸을 수 있는가: 최신 방법 중에는 few-shot branch를 이미 포함한 경우도 있어, 단순 reference 추가가 충분히 새로운 방법이 아닐 수 있음. 또한 후보 방법마다 source 학습, prompt, backbone, target protocol이 달라 최고 모델 선정 기준이 불명확할 수 있음.
- 교수님이 판단해주면 다음 주 무엇이 바뀌는가: 선정 기준과 첫 구현체를 확정한 뒤, 0-shot 재현 → 정상 시제품 1/2/4-shot 변형 → map·metric 비교 순서로 진행함.
