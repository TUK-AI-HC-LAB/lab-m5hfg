### 이번 주 변화

- 1단계로 각 방법이 무엇을 정상·이상 판단의 기준으로 쓰는지 표로 고정함.
- 2단계로 입력 정보, 학습·갱신 모듈, 중간 상태, 점수 함수를 같은 필드로 정리함.
- 3단계로 위 기준을 한글 비교 그림에 반영함.
- 공통 한계 분석, 원인 가설, 개선 논문 조사, 새 실험은 아직 진행하지 않음.

### 현재 연구 단계

- 현재 phase: Phase 2 - Evidence Reproduction.
- 이 phase라고 판단한 이유: 기존 방법의 입력·학습 상태·점수 계산과 재현 artifact를 같은 기준으로 연결했지만, 공통 limitation을 증명하는 새 진단 evidence는 아직 없음.
- 다음 phase로 가기 위해 필요한 evidence: 방법별 failure, 재현 결과, 원 논문 ablation을 함께 비교해 공통 한계 후보 하나를 선택할 근거.

## 2. 1단계: 이상 판단 기준 고정

### 기준 질문

각 방법은 **무엇을 정상·이상 판단의 기준으로 삼고, 테스트 이미지의 어떤 값이 그 기준과 어떻게 달라질 때 이상이라고 판단하는가?**

### 방법군 수준의 답

- *정상 데이터 기반 이상 탐지*: target 정상 이미지로 만든 정상 기준 상태와 테스트 이미지 특징의 차이로 이상을 판단함.
- *제로샷 이상 탐지*: target 정상 학습 이미지를 사용하지 않고, 텍스트·source 데이터·합성 데이터 등 target 밖의 보조 지식으로 만든 기준 상태와 테스트 이미지 특징의 관계로 이상을 판단함.
- 두 방법군 모두 최종 출력은 image-level 이상 점수와 pixel-level 이상 점수 지도지만, 그 전에 만드는 기준 상태와 점수 함수가 다름.

### 방법별 이상 판단 기준

| 방법 | 정상·이상 판단에 쓰는 기준 상태 | 테스트 이미지가 이상으로 판단되는 조건 | 근거 경로 |
|---|---|---|---|
| PatchCore | 정상 target 이미지의 대표 patch로 구성한 **정상 메모리** | 테스트 patch가 가장 가까운 정상 메모리 patch에서도 멀수록 | `meetings/2026-W31_brief.md` |
| SimpleNet | target 정상 특징과 Gaussian noise로 만든 가짜 이상 특징으로 학습한 **판별기** | 테스트 특징이 판별기에서 이상 특징 쪽으로 분류될수록 | `meetings/2026-W32_brief.md` |
| RD4AD | target 정상 특징을 보존하는 **one-class bottleneck embedding**과 학생 복원기 | teacher 특징과 학생이 복원한 특징의 차이가 클수록 | `meetings/2026-W34_brief.md` |
| AnomalyCLIP | source 보조 데이터로 학습한 물체와 무관한 **정상·이상 text embedding** | 테스트 위치 특징이 이상 text embedding과 더 유사할수록 | `meetings/2026-W37_brief.md` |
| WinCLIP | 사전학습 CLIP의 정상·이상 상태 단어 **prompt ensemble** | 테스트 image/window/patch 특징이 이상 prompt와 더 유사하고 정상 prompt와 덜 유사할수록 | `meetings/2026-W37_brief.md` |
| AA-CLIP | source 정상·이상 예시로 적응한 **anomaly-aware text anchor** | 테스트 patch 특징이 이상 anchor와 더 유사할수록 | `meetings/2026-W35_brief.md` |
| AnomalyVFM | 합성 normal/anomaly 데이터로 적응한 **VFM과 decoder** | decoder가 계산한 위치별 이상 점수가 클수록 | `meetings/2026-W38_brief.md` |

### 1단계 판단

- `정상 패치와 다르면 이상`은 PatchCore에는 직접 맞지만, SimpleNet과 RD4AD까지 설명하는 문장으로는 부족함.
- `텍스트 벡터의 흠집 특징과 비슷하면 이상`은 AnomalyCLIP·WinCLIP·AA-CLIP 일부를 설명하지만, AnomalyVFM에는 맞지 않음.
- 따라서 최종 그림은 방법군을 한 문장으로 단순화하지 않고, 각 방법 카드에 **기준 상태 → 점수 함수 → 이상 점수**를 따로 표시해야 함.

## 3. 2단계: 그림에 넣을 방법별 상태 고정

| 방법 | 입력 정보 | 학습·갱신되는 모듈 | 그림에 표시할 중간 상태 | 점수 계산 함수 |
|---|---|---|---|---|
| PatchCore | target 정상 이미지, 테스트 이미지 | 없음 | 정상 메모리 | 테스트 patch와 정상 메모리의 최근접 거리 |
| SimpleNet | target 정상 이미지, 테스트 이미지 | feature adapter, 판별기 | 적응된 정상 특징 | 판별기의 이상 분류 점수 |
| RD4AD | target 정상 이미지, 테스트 이미지 | OCBE, student decoder | one-class bottleneck embedding, 복원 특징 | teacher 특징과 복원 특징의 차이 |
| AnomalyCLIP | source 보조 데이터·mask, 테스트 이미지, 정상/이상 text prompt | object-agnostic prompt token | 정상·이상 text embedding, local visual embedding | 시각 특징과 text embedding의 cosine similarity |
| WinCLIP | 테스트 이미지, 물체 이름, 정상/이상 상태 단어 | 없음 | image/window/patch 특징, prompt ensemble | 다중 크기 시각-텍스트 유사도 집계 |
| AA-CLIP | source 정상·이상 이미지, 테스트 이미지 | text residual adapter, visual residual adapter | anomaly-aware text anchor, 적응된 patch 특징 | patch 특징과 text anchor의 cosine similarity |
| AnomalyVFM | 합성 normal/anomaly 이미지·mask, 테스트 이미지 | LoRA, decoder | 적응된 VFM 특징 | decoder가 산출하는 위치별 이상 점수 |

### 2단계 판단

- PatchCore·SimpleNet·RD4AD는 모두 target 정상 이미지를 입력으로 쓰지만, 각각 memory, 판별기, 복원기로 정상 기준 상태를 다르게 만듦.
- AnomalyCLIP·WinCLIP·AA-CLIP은 모두 CLIP 계열이지만, 학습 여부와 기준 상태가 다름. AnomalyCLIP은 prompt token, AA-CLIP은 residual adapter를 학습하고 WinCLIP은 학습하지 않음.
- AnomalyVFM은 text embedding과 유사도를 계산하는 CLIP 계열이 아니라, synthetic anomaly data로 VFM의 일부와 decoder를 적응시키는 방법임.

## 4. 3단계: 비교 그림 반영

![방법별 입력·학습 상태·점수 계산 비교](images/2026-W39_ad_method_comparison_ko.png)

- 상자에는 입력, 저장·학습된 중간 상태, 최종 출력을 표시함.
- 가는 화살표에는 특징 추출, 저장·학습, 유사도·거리·복원 차이 같은 계산 함수를 표시함.
- WinCLIP+는 target 정상 reference를 쓰는 few-normal-shot 확장판이므로 그림에서 제외함.
