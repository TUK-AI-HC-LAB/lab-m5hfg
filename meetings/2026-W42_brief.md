# 2026-W42 — QueCo 공통 프레임워크 추가 내역과 실행 결과

이 문서는 실제 실행한 수정본의 파일·코드와 `screw` 실행 결과를 기록한다. 기존 framework snapshot과 실행한 수정본이 동일하다는 비교 검증은 수행하지 않았다.

## 0. 작업·실행 기록

- QueCo 라이브러리·Trainer·설정 파일을 추가하고 registry와 공통 getter에 연결했다.
- MVTec AD `screw` 전체 test split 160장을 실행했다.
- CLIP·DINO 로딩, 추론, 7개 지표 계산, 공통 getter 수집, CSV 저장이 완료됐다. 종료 코드는 0이다.
- 해당 실행 중 Python 코드·YAML 파일은 수정하지 않았다.
- 새 학습은 수행하지 않았다. 현재 QueCo의 `train()`은 `predict(test_data)`를 호출한다.

## 1. 프레임워크에 추가·변경한 내용

### 1.1 `trainer/QueCo_lib/` 추가

실제 추가 위치는 프레임워크 최상위가 아니라 **`trainer/QueCo_lib/`**다. Python 파일 15개와 tokenizer 사전 1개가 있다.

| 파일 | 코드의 역할 |
|---|---|
| `__init__.py` | 모델 로딩 함수를 패키지에서 불러오도록 연결 |
| `model_load.py`, `build_model.py`, `QueCo.py` | CLIP 로딩·모델 구성·QueCo 모델 연산 |
| `prompt_ensemble.py` | PromptLearner 정의 |
| `simple_tokenizer.py`, `bpe_simple_vocab_16e6.txt.gz` | 텍스트 token 변환과 tokenizer 사전 |
| `visual_branch.py`, `similarity.py` | 이미지·패치 특징 비교 및 유사도 계산 |
| `fusion.py` | 브랜치·레이어 결합과 이상 점수·맵 처리 |
| `metrics.py` | Image·Pixel 평가 지표 계산 |
| `config.py` | 추론 설정과 기본값 처리 |
| `analysis.py` | fusion diagnostics 및 시각화 저장 함수 |
| `pose_aux.py` | pose 보조 처리 |
| `transform.py`, `utils.py` | 변환 및 보조 함수 |

패키지 안의 모듈을 참조하는 import는 상대 import로 연결됐다.

```python
# trainer/QueCo_lib/__init__.py
from .model_load import *

# trainer/QueCo_lib/prompt_ensemble.py
from .simple_tokenizer import SimpleTokenizer as _Tokenizer

# trainer/QueCo_lib/QueCo.py
from .transform import *
```

라이브러리 내부에는 정규화 연산이 있다. 아래 “CLIP 정규화 변환 미추가”는 **Trainer에 별도의 ImageNet → CLIP 입력 변환을 추가하지 않았다는 뜻**이며, 라이브러리의 모든 정규화 연산을 삭제했다는 뜻이 아니다.

### 1.2 `trainer/trainer_ourzad.py` 추가

클래스 이름은 `Trainer_OurZAD`이며 공통 `Trainer`를 상속한다. 라이브러리는 `from .QueCo_lib ...` 형식으로 불러온다.

공통 실행기 연결을 위해 `train()`에서 다음 기록을 수행한다.

1. `dataset_name`을 저장하고 `evaluation_results`를 빈 목록으로 초기화한다.
2. `predict(test_data)`를 호출한다.
3. 반환된 지표 7개에 이름을 붙인다.
4. 기존 공통 열과 연결하는 alias를 추가한다.
5. 기록을 `evaluation_results`에 넣고 7개 반환값도 유지한다.

| 반환 순서 | Trainer 기록 이름 | 공통 CSV 열의 기준 이름 |
|---:|---|---|
| 1 | `image_auroc` | `image_auroc`, `auroc` |
| 2 | `image_ap` | `image_ap` |
| 3 | `image_f1` | `image_f1` |
| 4 | `full_pixel_auroc` | `pixel_auroc` |
| 5 | `pixel_ap` | `pixel_ap` |
| 6 | `pixel_f1` | `pixel_f1` |
| 7 | `pixel_aupro` | `pixel_aupro`, `pro` |

```python
record["auroc"] = record["image_auroc"]
record["pro"] = record["pixel_aupro"]
record["saliency_cr_f1"] = -1
self.evaluation_results.append(record)
return raw_metrics
```

`saliency_cr_f1`은 별도 미계산 지표로 `-1`을 기록한다. Pixel F1은 별도 값으로 저장된다.

현재 Trainer에는 별도의 ImageNet → CLIP 입력 정규화 변환, batch 크기를 1로 강제하는 추가 검사, test 이미지를 최소 2장으로 제한하는 추가 검사가 없다.

### 1.3 registry에 `queco` 등록

`component_registry.py`의 `METHOD_REGISTRY`에 다음 항목이 있다.

```python
"queco": MethodSpec(
    "trainer.trainer_ourzad",
    "Trainer_OurZAD",
    "queco",
    uses_backbone=False,
),
```

`queco` 선택 시 `Trainer_OurZAD` 클래스를 불러오고 `configs/queco.yaml`을 읽는다.

### 1.4 공통 backbone 로딩을 건너뛰는 처리 추가

현재 `MethodSpec`에는 **`uses_backbone: bool = True`가 추가돼 있다.** “uses_backbone 옵션이 없다”는 설명은 추가 전 상태이며 현재 코드에는 해당하지 않는다.

`MethodSpec.load_backbone()`에는 다음 분기가 있다.

```python
if not self.uses_backbone:
    return SimpleNamespace(name=backbone_name, seed=None)

module = importlib.import_module(self.backbone_module)
return module.load(backbone_name)
```

`main_net.py`는 기존처럼 `method_spec.load_backbone(backbone_name)`을 호출한다. QueCo는 이 함수에서 실제 공통 backbone 대신 이름·seed를 가진 객체를 받는다. CLIP·DINO는 QueCo Trainer의 `initialize_model()`에서 로딩한다.

`uses_backbone`을 별도로 지정하지 않은 registry 항목은 기본값 `True`를 사용한다. 다른 방법의 실제 재실행 검사는 이번에 수행하지 않았다.

### 1.5 공통 metric getter 확장

`trainer/trainer.py`의 `get_evaluation_metrics()`에 선택 지표가 추가됐다.

기존 매핑은 유지된다.

```python
metrics_map = {
    "auroc": "auroc",
    "full_pixel_auroc": "pixel_auroc",
    "pro": "pro",
    "saliency_cr_f1": "sal_f1",
}
```

추가된 항목은 다음과 같다.

```python
optional_metrics = (
    "image_auroc", "image_ap", "image_f1",
    "pixel_ap", "pixel_f1", "pixel_aupro",
)
for key in optional_metrics:
    if any(key in record for record in self.evaluation_results):
        metrics_map[key] = key
```

`evaluation_results`에 해당 키가 있는 경우에만 추가 지표를 수집한다. 각 지표의 `min`, `max`, `mean`, `std` 열을 만든다. 값이 없거나 `-1`인 기록은 유효값 집계에서 제외하며, 유효값이 없으면 해당 통계값에 `-1`을 기록한다.

이번 평가 지표 계산은 QueCo 라이브러리의 metric 함수에서 수행됐다. 공통 getter는 계산된 값을 수집·집계한다. 실행기는 `train()`의 7개 반환값을 직접 unpack하지 않고 getter 결과를 CSV로 저장한다.

### 1.7 패키지·CLIP·DINOv2 가중치와 실행 확인

이번 실행은 기존 WSL Python 환경과 기존 가중치 캐시를 사용했다. 해당 실행 중 새 패키지 설치나 새 가중치 다운로드는 수행하지 않았다.

확인한 설치 버전은 다음과 같다.

| torchvision | 0.26.0+cu128 |
| torchmetrics | 1.9.0 |
| ftfy | 6.2.0 |
| regex | 2026.7.19 |
| scipy | 1.18.0 |

CLIP 가중치 파일 `ViT-L-14-336px.pt`, DINOv2 가중치 파일 `dinov2_vitb14_reg4_pretrain.pth`의 존재를 확인했다. 실제 실행에서 CLIP ViT-L/14@336px와 DINOv2 `dinov2_vitb14_reg` 모델 로딩이 완료됐다.

이번 실행 범위는 screw 한 카테고리다. **전체 15개 카테고리 실행은 이번 수정본으로 수행하지 않았다.**

## 2. 실제 실행 흐름

`main.py` → registry의 `queco` 선택 → 공통 Dataset·DataLoader 생성 → `main_net.py`의 Trainer 생성·load → QueCo 내부 CLIP·DINO 로딩 → `train()` → `predict(test_data)` → 지표 7개 계산·기록 → 공통 getter → `main_run.py`의 CSV 저장.

추론은 테스트 이미지 특징 bank 구성과 이미지별 점수·맵 계산으로 구성된다. 정상 train 320장의 loader도 만들어졌지만 이번 QueCo 추론에서 학습에 사용하지 않았다.
