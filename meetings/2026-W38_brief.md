## 1. 서론

### 1.1 연구 배경과 중요성

- Vision anomaly detection은 제품 이미지에서 정상과 다른 부분을 찾고, 이미지 전체의 불량 여부와 결함 위치를 출력하는 연구임.
- 실제 공정에서는 새 제품마다 이상 label을 많이 모으기 어렵기 때문에, target 제품의 이상 label 없이 적용하는 방법이 중요함.
- 최근에는 ImageNet feature를 normal memory와 비교하는 방법 [4], 정상 image만으로 판별기를 학습하는 방법 [5], teacher feature를 복원하는 방법 [6], CLIP/VLM을 활용하는 방법 [1, 2, 7], synthetic anomaly로 vision foundation model을 적응시키는 방법 [3]이 함께 연구됨.

### 1.2 기존 접근의 큰 계열과 한계

- normal-reference 계열: target 정상 image feature를 기억하거나 비교 기준으로 사용함 [4, 5].
  - 장점: target 제품의 정상 모양을 직접 기준으로 삼을 수 있음.
  - 한계: target 정상 image의 확보·저장·비교 비용이 필요하며, target을 전혀 보지 않는 설정과 같은 protocol이 아님.
- representation adaptation 계열: source 또는 synthetic data로 encoder·adapter·prompt 일부를 갱신함 [1, 3, 6].
  - 장점: 정상과 이상을 구별하기 좋은 표현을 만들 수 있음.
  - 한계: 어떤 data로 무엇을 갱신했는지에 따라 target zero-shot의 의미와 비교 조건이 달라짐.
- pretrained VLM 계열: image-text similarity와 prompt로 target 학습 없이 score를 계산할 수 있음 [1, 2].
  - 장점: 별도 target model training 없이 적용 가능함.
  - 한계: WinCLIP+처럼 target 정상 reference를 쓰는 조건은 pure zero-shot과 분리해야 함 [2].

### 1.3 우리가 집중하는 접근과 남은 문제

- 집중 접근: 서로 다른 방법을 성능 숫자만으로 나열하지 않고, 정상·이상 판단 신호가 representation과 scoring module을 거쳐 output으로 바뀌는 공통 흐름을 만드는 것.
- 이 접근이 필요한 이유: PatchCore의 memory distance, SimpleNet의 synthetic anomaly 판별, RD4AD의 feature reconstruction, CLIP 계열의 similarity는 모두 이상 점수를 만들지만 정상 기준 상태와 score 산출 방식이 다름.
- challenge 1: 여섯 방법의 입력·중간 상태·학습 상태·점수화 방식이 한 표나 그림에서 분명히 분리되지 않았음.
- challenge 2: AnomalyVFM은 논문과 공개 repository의 dataset/config가 완전히 동일하지 않아, 공개 실행만으로 strict 논문 재현을 주장할 수 없음.

### 1.4 원인 가설

- 현재 limitation: method 이름과 평균 AUROC만 나열하면 normal memory, reconstruction feature, prompt, adapted visual feature처럼 서로 다른 중간 상태와 score 산출의 차이가 가려짐.
- 원인 가설 H1: 방법을 `입력 → 정상·이상 표현 → 비교/복원/유사도 함수 → score/map`의 같은 흐름에 놓고, 갱신되는 상태와 입력 data의 역할을 표시하면 공통점과 핵심 차이가 동시에 드러남.
- H1이 맞다면: 여섯 방법은 공통적으로 visual representation에서 image score·pixel map을 내지만, 정상 기준을 보관·복원·텍스트화·합성 학습하는 분기에서 다르게 배치되어야 함.

### 1.5 이번 주 선택한 방향

- 후보 A: 바로 새 방법을 설계함.
  - 판단: 보류.
  - 이유: 기존 방법이 어떤 information protocol에서 다른지 먼저 그림과 raw evidence로 구분하지 않으면 새 방법의 차별점을 정의할 수 없음.
- 후보 B: AnomalyVFM 실행 조건을 고정하고, 방법군 비교 그림의 공통 표현 규칙을 먼저 정의함.
  - 판단: 선택.
  - 이유: Phase 2 재현 evidence와 이후 limitation analysis에 모두 필요한 기준선임.

### 1.6 이번 주 기여 또는 검토 초점

- 핵심 판단: 향후 방법 비교는 모델 이름이나 평균 점수보다 `정상·이상 신호`, `학습·갱신 상태`, `score 산출 함수`, `image/pixel output`을 먼저 표시해야 함. target data 사용은 비교 조건으로 함께 기록함.
- evidence: `meetings/2026-W37_brief.md`, `method8/source/run_anomalyvfm_paper_protocol_wsl.sh`.

## 2. 사전 지식과 문제 정의

### 배경

- target domain은 실제로 판별하려는 새 제품 데이터셋임. source domain은 target에 적용하기 전에 model/prompt/adapter를 학습시키는 데이터셋임.
- target normal reference는 target의 정상 이미지를 query와 비교하기 위해 따로 제공하는 정보임. target data를 학습하지 않아도 reference를 쓰면 target-free zero-shot과는 다른 protocol임.

### 기술 용어

- *normal memory* [4]: training normal image에서 얻은 feature 중 정상 기준으로 남겨 둔 feature 집합. query feature와의 거리를 계산하는 기준임.
- *target normal reference* [2]: target 범주의 정상 image를 query와 비교하기 위해 제공한 이미지. WinCLIP+의 few-normal-shot 조건에서 사용함.
- *source adaptation* [1]: source anomaly data로 prompt 또는 model 일부를 갱신한 뒤 target에 적용하는 절차.
- *synthetic anomaly training* [3]: 생성한 normal/anomaly image와 mask로 visual representation 일부를 이상 탐지에 맞게 갱신하는 절차.
- *image-level score*: 입력 이미지 한 장이 이상인지 나타내는 점수.
- *pixel-level anomaly map*: 이미지 위치별 이상 점수 지도. 결함 위치 평가에 사용함.

### 표기법

| 표기법 | 설명 |
|---|---|
| `D_s` | source 또는 synthetic training dataset |
| `D_t` | target dataset |
| `R_t` | target normal reference set |
| `f` | 고정 또는 갱신되는 visual/text representation |
| `s_I`, `s_P` | image-level score, pixel-level anomaly map |

### 정의

정의 1. method comparison schema.
각 방법을 `(1) 정상·이상 신호의 출처, (2) persistent intermediate state, (3) 갱신되는 module, (4) score 산출 함수, (5) image/pixel output`으로 기록하는 규칙임. target data 사용은 이 schema의 실행 조건으로 별도 기록함.

### 문제 정의

문제 1. 비교 가능한 anomaly-detection 방법군 요약.
PatchCore, SimpleNet, RD4AD, AA-CLIP, AnomalyCLIP, WinCLIP과 AnomalyVFM의 method description 및 실행 artifact가 주어졌을 때, 각 방법의 정상·이상 신호, 갱신되는 중간 상태, score 산출 함수, image/pixel 출력을 같은 표기 체계로 표시한다. target data 사용은 실행 조건으로 함께 기록한다. 목표는 향후 제안 방법의 차이와 검증해야 할 limitation을 판별할 수 있는 비교 그림을 만드는 것임.

## 3. 관련 연구

### 3.1 현재 문제를 푸는 큰 연구 흐름

- normal feature comparison:
  - 대표 논문: PatchCore [4].
  - 핵심: 정상 patch feature를 memory에 남기고 query patch와 최근접 정상 feature의 거리로 이상 점수를 계산함.
  - 현재 문제와의 연결: normal memory가 어떤 feature를 보관하고 거리로 어떻게 score를 만드는지 표시해야 함.
- reconstruction / one-class learning:
  - 대표 논문: SimpleNet [5], RD4AD [6].
  - 핵심: 정상 표현에서 벗어나는 정도를 판별 또는 복원 오차로 점수화함.
  - 현재 문제와의 연결: normal representation을 직접 학습하는지, reconstruction error 또는 classifier score를 쓰는지 구분해야 함.
- foundation-model adaptation / VLM:
  - 대표 논문: AnomalyCLIP [1], WinCLIP [2], AnomalyVFM [3], AA-CLIP [7].
  - 핵심: prompt, image-text similarity 또는 visual foundation feature를 anomaly detection에 활용함.
  - 현재 문제와의 연결: prompt similarity, window comparison, synthetic adaptation처럼 representation을 만드는 방식과 scoring module을 같은 색·같은 위치 규칙으로 분리할 필요가 있음.

### 3.2 현재 원인 가설에 대응하는 관련 연구

- AnomalyCLIP [1]은 VisA 같은 source domain으로 object-agnostic prompt를 학습하고 unseen target에 적용함.
- WinCLIP [2]은 zero-shot과 target normal reference를 쓰는 WinCLIP+를 구분함.
- AnomalyVFM [3]은 target dataset label 대신 synthetic anomaly data로 foundation model의 일부를 적응시키는 방향임.
- 이 세 연구는 모두 target label 부담을 줄이려 하지만, target data와 training data의 역할이 다르므로 H1의 비교 단위를 지지함.

### 3.3 이번 주 해결 후보 요약

- 후보 A: 여섯 방법의 결과 평균만 표로 비교.
  - 왜 가능성이 있는가: 빠르게 성능 차이를 볼 수 있음.
  - 왜 실패할 수 있는가: data access와 model update가 다른 protocol을 가릴 수 있음.
  - 이번 주 판단: 제외.
- 후보 B: 공통 intermediate state 중심의 비교 그림과 protocol 표기를 함께 사용.
  - 왜 가능성이 있는가: 모델·함수·입력 정보의 차이를 한 장에서 확인할 수 있음.
  - 왜 실패할 수 있는가: 과도하게 단순화하면 각 논문의 핵심 module이 사라질 수 있음.
  - 이번 주 판단: 선택. 실제 figure는 다음 artifact로 작성해야 함.

## 4. 선택한 방법 또는 절차

- 선택한 절차: AnomalyVFM 재현 준비와 여섯 방법을 설명하기 위한 그림의 공통 표현 규칙 정리.
- 기존 연구와의 차이: 새 detector를 제안하거나 그림 자체를 검증하지 않음. 그림은 기존 방법의 정상·이상 신호, intermediate state, scoring function을 읽는 사람이 한눈에 비교하도록 돕는 설명 자료임.
- comparison-figure 규칙:
  - 상자: **data 또는 중간 상태**만 표시함. 예: query image, normal memory, learned prompt, adapted visual feature, anomaly score/map.
  - 얇은 화살표: **function, model, module**만 표시함. 예: frozen encoder, trainable adapter, nearest-neighbor distance, similarity, aggregation.
  - 색상 legend: 회색=입력 data, 파랑=frozen representation/state, 주황=trainable/updated state, 초록=target normal reference 또는 normal memory, 보라=synthetic/source supervision, 진한 남색=최종 score/map으로 고정할 예정임.
  - data 역할은 상자 테두리나 `source train`/`synthetic train`/`target reference`/`target test only` 표기로 명시함. 이는 핵심 흐름을 보완하는 조건 표기이며 색만으로 판단하게 하지 않음.
- AnomalyVFM 실행 절차: official code revision을 WSL에 두고, 논문에 서술된 10,000 synthetic images, 768px, LoRA rank 64, AdamW lr 0.0001, 500 steps 조건을 script에 기록함. released code/data가 논문 당시 구성과 다름은 실행 결과 해석에서 분리함.

- AnomalyVFM은 논문 [3]의 공개 조건과 official released repository의 현재 구현을 분리해 기록함.
- 방법군 비교는 동일 AUROC의 절대값보다 정상 기준 상태와 score 산출 방식이 무엇인지로 먼저 구분하고, data access는 실행 조건으로 함께 기록함.

### 평가 지표

- AnomalyVFM 평가가 완료되면 Image AUROC, Pixel AUROC, AUPRO를 raw CSV로 기록할 예정임. 현재는 metric 값 없음.

### 데이터셋

- AnomalyVFM training input: released synthetic normal/anomaly image 10,000장 subset.
- target evaluation 예정: MVTec AD와 VisA. 현재 PC에 준비된 target dataset만 범위에 포함함.
- 원본 dataset, model weight, virtual environment는 repository 또는 Obsidian에 복사하지 않음.

### 실험 1: AnomalyVFM paper-condition 실행 준비 및 중단 기록

#### 질문

- AnomalyVFM의 공개 code에서 논문에 서술된 training 핵심 조건을 재현 가능하게 남길 수 있는가?

#### 가설

- H1: dataset subset, training command, official revision을 script에 고정하면 나중에 동일한 준비 상태에서 실행을 재개할 수 있음.

#### 설정

- upstream: `https://github.com/MaticFuc/AnomalyVFM`, revision `4da96b493a0b12e4e380fa5bf6573c126342855c`.
- model: RADIOv2.5 ViT-L, LoRA rank 64.
- training: 768px, batch size 32, AdamW, learning rate `0.0001`, 500 steps, seed 12.
