## 1. 서론

### 1.1 연구 분야: Vision Anomaly Detection

- Vision anomaly detection은 정상 이미지 중심의 학습으로, 테스트 이미지의 이상 유무와 이상 위치를 함께 찾는 분야임 [1]. 산업 검사에서는 결함 유형을 미리 모두 모으기 어렵기 때문에, 정상 train 이미지와 테스트 시점의 정상·이상 이미지를 사용하는 설정이 중요함.
- 출력은 이미지 전체의 이상 점수와 픽셀별 anomaly map임. 전자는 불량품 선별, 후자는 작업자가 결함 위치를 확인하는 데 사용됨.
- MVTec AD는 5개 texture와 10개 object로 구성되며, test 이미지의 결함 mask가 있어 image-level과 pixel-level 성능을 동시에 평가할 수 있음 [1].

### 1.2 기존 접근과 trade-off

- 재구성 기반 방법은 정상 이미지를 복원하고 입력과 복원의 차이로 이상을 찾음. 복잡한 texture에서는 정상 패턴 복원이 어려울 수 있고, 강한 decoder가 이상도 복원할 수 있다는 한계가 보고됨 [1].
- memory bank 기반 방법은 사전학습 CNN 특징을 정상 memory와 비교함. PatchCore는 높은 성능을 보이지만, 저장·최근접 검색이 추론 지연과 메모리 부담으로 이어질 수 있음 [3].
- teacher-student distillation 기반 방법은 정상 train 이미지에서 teacher와 student의 특징을 맞추고, 테스트 때 특징 차이를 이상 score로 사용함. RD4AD는 이 계열에서 encoder-to-decoder의 역방향 흐름과 bottleneck을 사용해 memory bank 없이 특징 차이를 키우려 함 [1].

### 1.3 RD4AD가 해결하려 한 문제와 남은 한계

- RD4AD의 선택 이유: memory bank 검색 없이, 고정된 ImageNet teacher 특징과 student decoder 복원 특징의 cosine distance로 image score와 anomaly map을 만들 수 있음 [1].
- RD4AD 원 논문은 `transistor`에서 위치 성능이 낮은 원인으로, 모델이 부품의 옮겨진 위치를 찾지만 정답 mask는 원래 위치까지 포함하는 annotation 불일치와 context 관계 부족을 제시함 [1].

### 1.4 현재 관찰과 원인 가설

- 관찰: 재현 결과에서 `transistor` Pixel AUROC는 92.30%, AU-PRO는 78.30%로 전체 평균 97.79%, 93.97%보다 낮음.
- H2: 이 낮은 위치 성능은 단순한 seed 변동만이 아니라, (a) 정답 annotation과 모델 반응 위치의 불일치 또는 (b) context 관계 부족과 관련될 수 있음.
- H2의 두 원인은 아직 분리되지 않았음. 따라서 먼저 입력·정답 mask·anomaly map을 비교하는 진단이 필요함.

### 1.5 이번 주 검토 초점

- 재현 성공 자체가 아니라, 재현 결과와 기존 논문을 이용해 RD4AD의 다음 한계 가설을 검토 가능한 형태로 좁히는 것임.

## 2. 사전 지식과 문제 정의

### 기술 용어

- *teacher encoder* [1]: ImageNet 사전학습 WideResNet-50-2로 여러 수준의 특징을 고정된 방식으로 추출함.
- *one-class bottleneck embedding* [1]: 정상 특징의 핵심 정보는 남기고 이상 교란은 줄이도록 학습하는 중간 표현.
- *student decoder* [1]: bottleneck embedding에서 teacher의 여러 수준 특징을 복원하는 네트워크.
- *Image AUROC / Pixel AUROC* [1]: 이미지 전체 이상 판별과 픽셀 위치 찾기 성능. 높을수록 좋음.
- *AU-PRO*: 공식 코드가 계산하는 결함 영역 단위 위치 성능. 논문 핵심 평균과 직접 비교하지 않음.

### 표기법

| 표기법 | 설명 |
|---|---|
| `x` | 입력 이미지 |
| `T(x)` | teacher encoder의 여러 수준 특징 |
| `B` | one-class bottleneck embedding |
| `S(B(T(x)))` | student decoder가 복원한 특징 |

### 정의

정의 1. 특징 복원 차이.
teacher 특징과 student decoder가 복원한 특징의 cosine distance임. 이 값이 큰 위치를 이상 후보로 사용함.

### 문제 정의

문제 1. RD4AD MVTec AD 재현.
각 범주의 정상 train 이미지로 bottleneck과 decoder를 학습하고, 테스트 이미지의 image anomaly score와 pixel anomaly map을 예측함. 성공 기준은 15개 범주 평균 I-AUROC와 P-AUROC가 논문 [1] 보고값에 얼마나 가까운지임.

## 3. 관련 연구

### 3.1 방법 계열 비교

| 방법 | 정상성 기준 | 강점 | 문헌에서 지적된 trade-off |
|---|---|---|---|
| PatchCore [3] | normal memory와 최근접 거리 | 강한 patch 기반 비교 | memory bank 저장·검색 비용 |
| SimpleNet [2] | 정상 특징과 가짜 이상 특징의 판별 경계 | memory 검색 없이 빠른 판별 | 가짜 이상 생성 방식이 실제 결함 전체를 대표하지 않을 수 있음 |
| RD4AD [1] | teacher 특징과 decoder 복원 특징의 cosine distance | reverse decoder와 bottleneck으로 정상 특징 복원 | transistor 사례에서 annotation 불일치와 context 관계 부족 가능성 |

## 4. 선택한 방법 또는 절차

- 공식 구현체 revision `6554076872c65f8784f6ece8cfb39ce77e1aee12` 사용.
- WideResNet-50-2, 입력 256, batch size 16, 범주당 200 epoch, seed 111, 10 epoch마다 평가.
- Adam learning rate 0.005, beta `(0.5, 0.999)`, anomaly map Gaussian smoothing sigma 4 사용.
- 최신 환경 호환을 위해 pandas `append()`와 NumPy `np.bool`만 최신 API로 교체함.
- 데이터 경로·범주 선택·결과 CSV 인자만 추가했으며, 모델 구조·loss·optimizer는 변경하지 않음.

### 실험 2: transistor 위치 성능 진단

- 질문: 낮은 `transistor` 위치 성능은 정답 annotation 불일치인가, 아니면 RD4AD anomaly map의 실제 위치 오탐인가?
- H2: 원 논문의 설명처럼 misplaced 부품에서 모델 반응은 옮겨진 위치에 집중하지만, 정답 mask는 원래·옮겨진 위치를 함께 포함할 수 있음. 그 경우 낮은 Pixel AUROC/AU-PRO의 일부는 annotation과 예측의 공간적 불일치로 설명될 수 있음 [1].
- H2가 맞다면: anomaly map의 높은 영역이 실제 옮겨진 부품 위치에 모이고, 정답 mask와 어긋나는 위치가 확인되어야 함.
- 실제 결과: 아직 진단 그림을 생성하지 않았음. 현재 raw score만으로는 annotation 불일치와 context 관계 부족 가설을 구분할 수 없음.
- 예정 evidence: 입력·정답 mask·anomaly map을 같은 이미지 단위로 저장한 figure와 그 원본 score map.

## 6. 논의

- H1은 지지됨. 두 지표 모두 논문 평균에서 1.0%p 이내이고, 논문 본문 조건 재실행에서도 15개 범주 값이 모두 반복됨.
- 지금 주장할 수 있는 것: 현재 WSL GPU 환경에서 RD4AD의 논문 본문 설정으로 MVTec AD 평균 성능을 재현할 수 있음.
- 지금 주장할 수 없는 것: `transistor`의 낮은 위치 성능이 RD4AD 모델의 context 관계 한계 때문이라는 결론. 현재는 raw metric과 기존 논문을 연결한 가설 단계임.
- 기존 논문이 제공한 두 후보 원인: RD4AD [1]은 annotation-예측 불일치와 context 관계 부족을 제시함.
- 다음 판단: 개선 모듈을 바로 추가하지 않고, 먼저 transistor의 공간적 오류를 진단함. annotation 불일치가 주원인이면 평가·annotation 해석 문제로 다루고, 실제 오탐이면 context 정보를 보완하는 방법을 다음 후보로 검토함.
