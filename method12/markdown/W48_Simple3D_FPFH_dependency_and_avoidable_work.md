# W48 Simple3D — FPFH 의존 관계와 생략 가능한 계산량

완료 샘플 24/24개. 각 샘플의 40·80·120 이웃 스케일을 따로 측정함.

## 1. 현재 특징이 사용되는 경로

```text
전체 점군 P (좌표는 모두 검색 후보로 유지)
 ├─ CPU 법선 계산
 ├─ STEP 512 + Radix → 모든 점의 120-NN (40/80/120 접두부 재사용)
 │   └─ SPFH → FPFH 40/80/120 → [40,80,80,120] 연결 (132차원)
 └─ FlashFPS hybrid → 대표점 4,096개 → 각 대표점의 128-NN
     └─ 위 FPFH를 원래 이웃 순서대로 모아 평균 → 대표점 특징 4,096개
         ├─ 학습: 정상 메모리뱅크 후보 → coreset
         └─ 테스트: 정상 뱅크까지 최근접 특징 거리 → 대표점 이상 점수
             → 원본 점에 Top-3 보간 → 1,024점·12-NN 평활화 및 보간
             → 포인트 이상 점수 → 상위 80점 평균으로 물체 점수
```

대표점 4,096개만 FPFH를 계산하면 안 됨. 실제 집계는 각 대표점 주변 128개 점의 FPFH를 사용하기 때문임. 최종 dense 점수 보간은 좌표와 대표점 점수를 사용하며 원본 모든 점의 FPFH를 다시 읽지는 않음.

## 2. 무엇을 직접 쓰고, 무엇이 추가로 필요한가

- P: 원본 모든 점. N은 원본 점 개수.
- U: 4,096×128 집계 인덱스에서 중복을 제거한 점 집합. 이 점들의 FPFH가 직접 필요함.
- V_k = U ∪ N_k(U): U의 FPFH를 계산하는 데 필요한 SPFH 행 집합. U 자신의 SPFH도 포함함.
- W_k = V_k ∪ N_k(V_k): V_k의 SPFH를 계산하는 데 좌표·법선이 필요한 점 집합.
- N_k는 실제 CUDA 코드의 이웃 열 1..k−1을 뜻함. 세 스케일은 같은 정렬된 120-NN의 접두부를 사용함.
- 0거리 이웃·중복 좌표의 추가 생략은 적용하지 않은 보수적 충분 집합임. 따라서 제시한 생략률은 이 의존 집합으로 보장할 수 있는 행 생략률임.
- 생략 가능: FPFH 출력 행 N−|U|, SPFH 및 120-NN 쿼리 행 N−|V_120|. 법선 출력은 N−|W_120|까지 후보지만 별도 검증이 필요함.
- 법선을 W에서만 계산하더라도 그 법선의 추정을 위한 주변 좌표는 P 전체에서 찾아야 함. 검색 대상 점을 U/V/W로 잘라내는 방식이 아님.
- 120-NN 인덱스 구조는 여전히 P 전체에 대해 필요함. 쿼리 행 생략률을 인덱스 구성 비용이나 전체 추론 절감률로 해석하지 않음.

## 3. 사전 질문·가설·검증 방식

- 질문: 최종 특징에 쓰이지 않는 FPFH와, 그 의존성을 고려해도 쓰이지 않는 SPFH/쿼리 행이 충분히 남는가?
- 가설 H1: U보다 의존 집합 V/W가 커지므로 직접 사용률만 보면 절감량이 과대평가됨.
- 가설 H2: 의존 집합이 거의 P 전체를 덮는 카테고리에서는 결과를 보존하는 선택 계산의 이점이 작음.
- 기대: V/W가 전체에 가까우면 후보를 축소·제외하고, 작은 경우에만 후속 선택 계산 구현을 검토함.
- 고정: 현재 FlashFPS hybrid, STEP512/Lloyd50+Radix, 4,096 대표점·128 이웃, FPFH40/80/120. 모델 코드 변경 없음.
- 표본: 6개 카테고리 각각 train 0번, test 0번·중간·마지막. 정상/결함 라벨이나 mask로 필요한 점을 선택하지 않음. 전체 52개에 일반화하지 않음.
- 검증: W 바깥 법선을 0으로, V 바깥 SPFH를 0으로 둔 별도 검증 배열을 전체 커널에 입력함. U의 FPFH와 동일 순서 128-NN 집계값이 dense 기준과 bitwise 같은지 검사함.
- 이 검증은 계산을 실제 생략한 구현이 아님. 최종 메모리뱅크·전체 점수·AUROC/AP 재평가와 속도 측정은 이번 1~2단계의 범위가 아님.

## 7. 1~2단계의 결론

**현재 표본에서는 ‘직접 사용하는 FPFH만 남기면 주요 이웃 탐색도 크게 줄어든다’는 기대를 지지하지 않음.**

- MiniShift 12개 표본: 직접 쓰는 FPFH는 평균 53.8465%이지만, 그 특징의 의존성을 계산하려면 SPFH 및 120-NN 쿼리가 평균 99.9403%의 점에서 필요함. 이 경로로 생략할 수 있는 쿼리 행은 0.0597%임.
- Anomaly-ShapeNet 12개 표본: 직접 쓰는 FPFH가 평균 99.9115%, SPFH/쿼리 필요율은 100%임. 이 경로의 쿼리 행 생략 후보가 없음.
- 모든 표본에서 법선의 의존 집합은 100%를 덮음. 실제 커널에서 읽지 않는 0거리 이웃을 제외해도 SPFH 의존 집합의 크기는 바뀌지 않았음.
- 이는 고정한 집계 규칙(4,096×128), 특징 정의, 현재 표본에서의 의존성 분석임. 모든 카테고리·설정에 대한 불가능성 증명이나 가능한 모든 알고리즘의 계산량 하한은 아님.

### 무엇이 남고 무엇을 보류하는가

- 남는 후보: MiniShift에서 직접 쓰지 않는 FPFH **출력 행**을 생략하는 것. 그러나 이 방식만으로는 SPFH·이웃 탐색을 크게 생략하지 못함.
- 이전 capsule Radix 실행에서 세 스케일의 SPFH+FPFH 계산 구간은 합계 약 40.79ms, 전체 추론은 1,440.95ms였음. 이 계산 구간 전체도 전체 추론의 약 2.8%이며, 출력 행 선택으로 줄일 수 있는 것은 그중 일부임. 실제 시간 절감량을 측정한 결과는 아님.
- 근거: [단계별 측정](../source/results/step_radix_e2e_20261118/stage_comparison.csv) · [전체 추론 비교](../source/results/step_radix_e2e_20261118/category_comparison.csv).
- 보류: 정확한 출력 유지가 목표인 이웃 탐색 대폭 생략 후보로 단순한 FPFH 출력 행 선택을 밀어붙이지 않음. 의존성이 거의 전체로 확장되는 것이 원인임.
- 이후 다른 방식으로 탐색 비용을 줄이려면, 전체 점을 버리는 것이 아니라 탐색 결과/구조를 공유하거나 특징·집계 정의 자체를 바꾸는 별도 연구 질문이 필요함. 이번 요청에서는 그 새 알고리즘 구현이나 정확도 손실을 허용하는 실험을 진행하지 않았음.
